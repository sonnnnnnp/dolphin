# Dolphin 設計メモ

作り直し版（`main`）の要件と言語仕様をまとめる。旧実装（`archive/cpp`）の構文をもとにしている。処理系の構成は [architecture.md](architecture.md) にまとめる。

状態の書き方:

- **確定**: 決まったこと
- **案**: 提案。決めるまで変更してよい
- **未決**: 選択肢だけ挙げて、まだ決めていないこと

---

## 1. 目的と方針

- インタプリタ言語の仕組みを理解するために、処理系を自作する
- シンタックスはユニークにする（`@` 変数、`[ ]` 呼び出し、`( )` ブロック、`#` return）
- 実用は目的ではないが、実際に使っても困らない水準を目指す
- 最終的にバックエンド API とデスクトップアプリを書けるようにする

## 3. 字句（Lexer）

| トークン | 定義 | 例 |
|---|---|---|
| `VAR` | `@` + 識別子。すべての変数（グローバルもローカルも）に使う（2026-10-11 確定。旧 `GLOBAL` / `LOCAL` を統一） | `@score` |
| `IDENT` | 英字か `_` で始まり、英数字と `_` が続く | `add`, `arr_len` |
| `NUMBER` | `数字+ [ "." 数字+ ]` | `10`, `1.5` |
| `STRING` | `"` で囲む。中の `@識別子` は値に展開する。`\"` `\\` `\n` `\@` でエスケープ。`@` の後が識別子でなければただの文字。`$` は特別扱いしない（2026-10-11 確定） | `"Hello, @name!"`, `"$100"` |
| キーワード | `if` `else` `while` `for` `in` `break` `continue` `true` `false` `nil` | `for` `in` `nil` は 2026-10-11 に追加 |
| 記号 | `[ ] ( ) { } , : = := # .` | |
| 演算子 | `+ - * / % == != < <= > >= && \|\| !` | |
| `NEWLINE` | 改行。文の区切り | |

- `//` から行末まではコメント。旧実装と違い、行末コメントも許す（案）
- `[ ]` と `{ }` の中の改行は無視する。長い引数・配列・マップを複数行に書けるようにするため（案）
- `( )` の中の改行は無視しない。ブロック内の文の区切りに使うため

## 4. 文法（EBNF）

表記: `{ x }` は0回以上、`[ x ]` は省略可、`|` は選択、`"x"` は終端記号。

```ebnf
program     = { NEWLINE } { statement terminator } EOF ;
terminator  = NEWLINE { NEWLINE } | EOF ;

(* ---- 文 ---- *)
statement   = func_def
            | if_stmt
            | while_stmt
            | for_stmt
            | return_stmt
            | "break"
            | "continue"
            | assignment
            | expr_stmt ;

assignment  = variable ":=" expression                          (* 宣言 *)
            | variable { "{" expression "}" } "=" expression ;   (* 代入。添字つきは要素の書き換え *)
variable    = VAR ;

func_def    = IDENT "[" [ params ] "]" block ;
params      = VAR { "," VAR } ;

if_stmt     = "if" expression block
              [ { NEWLINE } "else" ( block | if_stmt ) ] ;
while_stmt  = "while" expression block ;
for_stmt    = "for" variable "in" expression block ;
return_stmt = "#" [ expression ] ;
expr_stmt   = expression ;

block       = "(" { NEWLINE } [ statement { NEWLINE { NEWLINE } statement } ] { NEWLINE } ")" ;

(* ---- 式（下ほど優先度が高い） ---- *)
expression  = or_expr ;
or_expr     = and_expr { "||" and_expr } ;
and_expr    = cmp_expr { "&&" cmp_expr } ;
cmp_expr    = add_expr [ ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) add_expr ] ;
add_expr    = mul_expr { ( "+" | "-" ) mul_expr } ;
mul_expr    = unary { ( "*" | "/" | "%" ) unary } ;
unary       = ( "-" | "!" ) unary | postfix ;
postfix     = primary { "{" expression "}" | "[" [ args ] "]" | "." member } ;
                                                      (* 添字は { }、値の呼び出しは [ ]（2026-10-11 確定） *)
member      = IDENT [ "[" [ args ] "]" ] ;      (* 名前空間の関数呼び出し、または変数の読み取り *)
primary     = NUMBER
            | STRING
            | "true" | "false" | "nil"
            | variable
            | call
            | IDENT                                   (* 関数名だけ = 関数値（5.8） *)
            | lambda
            | array_lit
            | map_lit
            | "(" expression ")" ;

call        = IDENT "[" [ args ] "]" ;
lambda      = "[" [ params ] "]" block ;
args        = expression { "," expression } ;
array_lit   = "{" [ args ] "}" ;
map_lit     = "{" ":" "}"
            | "{" entry { "," entry } "}" ;
entry       = expression ":" expression ;
```

### 4.1 文法上の注意

- **`(` の二重の役割**: `(` はブロックの開始と、式のグループ化の両方に使う。式の途中（二項演算子の後ろを除く）に `(` が来ても式は続かないので、`if @a > 0 (` の `(` はブロックと判定できる。`if (@a + @b) > 0 (` の先頭の `(` は式の始まりなのでグループ化になる
- **関数定義と呼び出しの区別**: どちらも `IDENT [ ... ]` で始まる。`]` の直後が `(` なら定義、それ以外なら呼び出し
- **括弧の役割分担**（2026-10-11 確定）: `[ ]` は呼び出し、`( )` はブロックとグループ化、`{ }` はデータ（配列・マップのリテラルと添字）。関数が値になっても、`@f[1]`（呼び出し）と `@a{1}`（添字）を見た目で区別できる
- **`{` の曖昧さ**: 式の直後の `{` は添字。`[ ]` `{ }` の中は改行を無視するので、`log[@a` と改行して `{1}` と書くと添字に読まれる。文の先頭に配列リテラルを置くときは、前の行と同じ `[ ]` の中に入れない
- **`else` の位置**: 旧実装では `)` の次の行に `else (` を書く。そのため `if` ブロックの後は、改行を読み飛ばして `else` があるか先読みする
- **`else if`**: 旧実装にはない。`else` の後に `if_stmt` を書けるようにして対応する（案）
- **`-` と `!` の単項演算子**: 旧実装にはない（`@x * -1` が動かない原因）。追加する（案）
- **配列とマップの区別**: どちらも `{` で始まる。最初の要素の後に `:` があればマップ、なければ配列。`{}` は空の配列、`{:}` は空のマップ
- **1行に複数の文**: 書けない。文は改行で区切る（旧 docs の `( @py = 472  @vy = 0 )` は不可）（案）

### 4.2 例

```
// 合計を返す
add[$a, $b] (
    # $a + $b
)

@nums := {10, 20, 30}
@i := 0
while @i < 3 (
    if @nums{@i} > 15 (
        log["@i 番目は 15 より大きい"]
    )
    else (
        @nums{@i} = add[@nums{@i}, 100]
    )
    @i = @i + 1
)
```

## 5. 意味論

### 5.1 変数とスコープ

| 項目 | 内容 | 状態 |
|---|---|---|
| `@x` | すべての変数。グローバルかローカルかは、宣言された場所で決まる（字句スコープ）。`$` は廃止 | 確定（2026-10-11） |
| 宣言 | `@x := 式`。いま入っているスコープに新しい変数を作る。同じスコープでの二重宣言はエラー。内側のスコープで同じ名前を宣言すると、外側を隠す | 確定（2026-10-11） |
| 代入 | `@x = 式`。外側を含めて、宣言済みの最も内側の `@x` を書き換える。宣言されていなければ**実行前エラー**（タイプミスを検出する） | 確定（2026-10-11） |
| トップレベルの変数 | そのファイルの変数。ファイル内のどの関数からも読み書きできる（旧 `@` の役目）。ほかのファイルとは別（5.7） | 確定（2026-10-11） |
| 関数内の変数 | 引数と、関数内で `:=` した変数。呼び出しごとに作られる | 確定（2026-10-11） |
| クロージャ | 関数値は、作られたときの外側のスコープの変数を捕まえる（共有する。コピーではない） | 確定（2026-10-11） |
| 未宣言の参照 | 実行前エラー（Resolver が検出する） | 案 |

旧実装との違い: 「最初の代入で宣言される」規則をやめた。クロージャが外側の変数を書き換えるのか、同名の新しい変数を作るのかを区別するため。

### 5.2 関数

| 項目 | 内容 | 状態 |
|---|---|---|
| 定義場所 | トップレベルのみ | 案 |
| 定義前の呼び出し | 実行前に全関数を登録し、定義より前の行から呼べるようにする | 案 |
| 引数 | 値渡し。ただし配列とマップは参照を渡す（7.1）。数が合わなければ実行前にエラー | 案 |
| 戻り値 | `# expr` で返す。`#` なしで終わったら「値なし」 | 案 |
| 関数値 | 関数を変数に入れたり、引数に渡したり、戻り値にしたりできる。5.8 | 確定（2026-10-11） |
| 再帰 | 可能 | 案 |

### 5.3 値と型

| 型 | 例 | 状態 |
|---|---|---|
| 数値 | `10`, `1.5`（内部は double） | 案 |
| 文字列 | `"dolphin"`。`"..."` 内の `@name` は展開される | 確定 |
| 配列 | `{1, 2, 3}` | 案 |
| マップ | `{"name": "Dolphin", "age": 3}`。5.4 | 確定（2026-10-06） |
| モジュール | `import["util.dol"]` の結果。5.7 | 確定（2026-10-11） |
| 関数 | `[@n] ( # @n + 1 )` や、`add` のような関数名。5.8 | 確定（2026-10-11） |
| 真偽値 | `true` / `false`。比較演算の結果も真偽値 | 確定 |
| 値なし | 戻り値のない関数の結果。`nil` と書ける（確定 2026-10-11）。JSON の `null` に当たる | 確定 |

旧実装はすべての値を文字列で持ち、計算のたびに数値へ変換していた。作り直し版では値に型を持たせる（案）。

- `if` / `while` の条件が真偽値でない場合は実行時エラーにする（案）
- `+` は数値どうしなら加算、文字列どうしなら連結。数値と文字列の混在は実行時エラー（案）

### 5.4 マップ

| 項目 | 内容 | 状態 |
|---|---|---|
| キー | 文字列のみ。リテラルのキーには式も書ける（`{@k: 1}`）が、値が文字列でなければ実行時エラー | 確定（2026-10-06） |
| 読み取り | `@m{"key"}`。キーがなければ実行時エラー。あるかどうかは `map_has` で調べる | 案 |
| 書き込み | `@m{"key"} = v`。キーがなければ追加、あれば上書き | 案 |
| 順序 | 追加した順を保つ（表示や将来の JSON 出力で順序が変わらないように） | 案 |
| 比較 | `==` はキーと値の組が同じなら true。順序は見ない | 案 |
| 表示 | `{"name": "Dolphin", "age": 3}`。空は `{:}`。配列やマップの中の文字列は `"` で囲む | 案 |
| 組み込み関数 | `map_len` `map_keys`（キーの配列）`map_has` `map_remove`（取り除いた値を返す） | 案 |

### 5.5 組み込み関数

引数の型や数が違うときは実行時エラー。文字列の位置と長さはすべて文字単位（`str_len["イルカ"]` は 3）。

| 分類 | 関数 | 内容 |
|---|---|---|
| 入出力 | `log[...]` | 引数を空白区切りで出力して改行 |
| | `input[]` | 1 行読んで文字列で返す（末尾の改行は除く） |
| ファイル | `file_read[path]` | ファイル全体を文字列で返す。UTF-8 として読めなければエラー |
| | `file_write[path, s]` | 文字列を書き込む。なければ作り、あれば置き換える |
| | `file_append[path, s]` | 文字列を末尾に足す。なければ作る |
| | `file_exists[path]` | ファイルかディレクトリがあるか（真偽値） |
| 文字列 | `str_len[s]` | 文字数 |
| | `str_concat[...]` | 値を文字列にしてつなげる |
| | `str_upper[s]` / `str_lower[s]` / `str_trim[s]` | 大文字・小文字・前後の空白を除く |
| | `str_contains[s, sub]` | 含むか（真偽値） |
| | `str_find[s, sub]` | 最初の位置。なければ -1 |
| | `str_replace[s, from, to]` | すべて置き換える |
| | `str_split[s, sep]` | 配列に分ける。`sep` が `""` なら 1 文字ずつ |
| | `str_join[arr, sep]` | 配列の要素をつなげる |
| | `str_sub[s, start, end]` | `start` から `end` の手前まで |
| 変換 | `to_str[v]` | `log` と同じ表示の文字列 |
| | `to_num[v]` | 文字列を数値に（前後の空白は無視）。変換できなければエラー |
| 配列 | `arr_len[a]` / `arr_push[a, v]` / `arr_pop[a]` | 長さ・末尾に追加・末尾を取り出す |
| | `range[a, b]` | `a` 以上 `b` 未満の整数の配列。`a >= b` なら空。1000 万要素まで |
| | `arr_map[a, f]` | 各要素に `f` を適用した新しい配列 |
| | `arr_filter[a, f]` | `f` が `true` を返した要素だけの新しい配列（`f` は真偽値を返す） |
| | `arr_each[a, f]` | 各要素に `f` を適用する（戻り値は使わない） |
| マップ | `map_len[m]` / `map_keys[m]` / `map_has[m, k]` / `map_remove[m, k]` | 5.4 |
| 数学 | `abs` `floor` `ceil` `round` `sqrt` | 引数 1 つ。`round` は 0.5 を 0 から遠いほうへ丸める |
| | `pow[a, b]` / `min[...]` / `max[...]` | べき乗・最小・最大 |
| | `random[]` / `random_int[min, max]` | 0 以上 1 未満 / `min` 以上 `max` 以下の整数 |

ファイル関数のパスは、実行したときのカレントディレクトリからの相対パス（`import` は呼び出したファイルのあるディレクトリから引くので、基準が違う）。読み書きに失敗したらエラー。文字コードは UTF-8 のみ。削除・一覧・ディレクトリ作成は未定（案）。

### 5.6 制御

| 項目 | 内容 | 状態 |
|---|---|---|
| `if` / `while` の条件 | 真偽値のみ。それ以外は実行時エラー | 案 |
| `for` | `for @x in 式 ( … )`。式は配列で、要素を順に `@x` に入れて本体を実行する。配列でなければ実行時エラー。本体は繰り返しごとに新しいスコープ（`@x` も繰り返しごとに別の変数）。回し始めた時点の配列の要素を使う（途中で書き換えても回す対象は変わらない） | 確定（2026-10-11） |
| マップ・回数指定 | マップは `for @k in map_keys[@m]`、回数は `for @i in range[0, 10]`（`range` は配列を返す。終わりの値は含まない） | 確定（2026-10-11） |
| `break` | いちばん内側の `while` / `for` を抜ける | 確定（2026-10-06） |
| `continue` | いちばん内側の `while` / `for` の次の繰り返しへ進む | 確定（2026-10-06） |
| 使える場所 | `break` / `continue` は `while` / `for` の中だけ。関数の中から外側のループは抜けられない（実行前にエラー） | 確定（2026-10-06） |
| 複合代入 | `+=` などは作らない。`@i = @i + 1` と書く | 確定（2026-10-11） |

### 5.7 モジュール（import）

```
@u = import["util.dol"]
log[@u.add[1, 2]]     // 関数を呼ぶ
log[@u.version]       // util.dol の @version を読む
```

| 項目 | 内容 | 状態 |
|---|---|---|
| 書き方 | `import[path]` はファイルを実行してモジュールを返す組み込み関数。結果を `@` 変数に入れて使う | 確定（2026-10-11） |
| 名前空間 | 名前空間つき（Python の `import util` に近い）。呼び出しは `@u.add[1, 2]` | 確定（2026-10-11） |
| `@` 変数のスコープ | ファイルごとに別。ほかのファイルの `@x` とはぶつからない。そのファイルの関数からは今までどおり読み書きできる | 確定（2026-10-11） |
| 外からの変数アクセス | `@u.name` で読める。`@u.name = v` のように外から書くのは構文エラー。書き換えたいときは、そのファイルに setter 関数を書く | 確定（2026-10-11） |
| 公開の範囲 | 絞る仕組みはなし。関数も `@` 変数も全部見える | 確定（2026-10-11） |
| 同じファイルを 2 回 import | 2 回目は 1 回目の結果を使う。実行は 1 回だけ（Python と同じ） | 確定（2026-10-11） |
| パスの基準 | import するファイルのあるディレクトリ。REPL ではカレントディレクトリ | 案 |
| 循環 import | 実行時エラー | 案 |
| 組み込み関数 | 名前空間をまたいでそのまま使える（`@u.log[...]` とは書かない） | 案 |
| 存在しない名前 | `@u.nope` や `@u.nope[]` は実行時エラー | 案 |
| 表示 | `<module "util.dol">`。名前は本体のあるディレクトリからの相対パス | 案 |
| `.名前[...]` | 常に関数呼び出し。モジュールの配列の要素は `@u.items{0}` で読める（添字が `{ }` になったため） | 案 |
| 文字列の中 | `"@u.name"` は `@u` だけが展開される（`.name` はそのまま文字）。モジュールの変数は `@u.name` を式として書く | 案 |
| エラーの表示 | import したファイルで起きたエラーは、そのファイルの行を引用し、import した位置を呼び出し履歴に載せる | 案 |

### 5.8 関数値とクロージャ

```
add[@a, @b] ( # @a + @b )              // 名前つきの定義（これまでどおり）
@f := add                              // 関数名だけを書くと、関数値になる
@inc := [@n] ( # @n + 1 )              // 無名関数
log[@f[1, 2], @inc[1]]                 // 変数の関数値は @f[...] で呼ぶ

make_counter[] (
    @n := 0
    # [] (
        @n = @n + 1
        # @n
    )
)
@c := make_counter[]
log[@c[], @c[]]                        // 1 2（@n は呼び出しをまたいで共有される）
log[arr_map[{1, 2, 3}, [@x] ( # @x * 2 )]]
```

| 項目 | 内容 | 状態 |
|---|---|---|
| 無名関数 | `[ 引数 ] ( 本体 )` は式。引数は `@` 変数。本体は関数と同じ（`#` で返す。改行で文を区切る） | 確定（2026-10-11） |
| 関数名 | `add` のように `[` を付けずに書くと関数値。組み込み関数（`log` など）も同じ。`import` は関数値にできない | 確定（2026-10-11） |
| 呼び出し | `式[ 引数 ]`。`IDENT[...]` は名前で呼ぶ、それ以外（`@f[1]`、`@make[][2]`、`@u.f` の結果など）は値を呼ぶ。`[ ]` は呼び出し専用で、添字は `{ }` | 確定（2026-10-11） |
| 捕まえるもの | 関数値は、作られた場所のスコープを参照で捕まえる（コピーしない）。外側の変数を書き換えると、関数値からも見える | 確定（2026-10-11） |
| ループの中で作る | `while` の本体は繰り返しごとに新しいスコープなので、本体で `:=` した変数は繰り返しごとに別になる | 確定（2026-10-11） |
| `break` `continue` | 無名関数の中からは、外側の `while` を抜けられない（関数と同じ） | 確定（2026-10-11） |
| 比較 | `==` は、同じ定義を同じスコープから取り出した関数値なら true（`@f == add`）。同じ無名関数でも、呼び出しごとに作られたものは別の値 | 案 |
| 表示 | `<関数 add>` / `<関数>`（無名）/ `<組み込み関数 log>` | 案 |
| 引数の数 | 呼び出すときに検査する（合わなければ実行時エラー） | 案 |
| モジュールの関数 | `@u.add`（`[` なし）は、`@u` の変数 `add` がなければ関数 `add` を関数値として返す | 案 |
| 組み込み関数からの呼び出し | `arr_map` などが関数値を呼ぶ。中で起きたエラーは、呼び出し履歴つきで報告する | 案 |
| メモリ | 関数値は自分を作ったスコープを参照するので、自分自身を持つ変数に入れると循環する。`Rc` では解放されない（`@a` が自分を含む配列と同じ扱い。architecture.md 6 章） | 案 |

## 6. 旧実装からの主な変更（案）

| 旧実装 | 作り直し版 | 理由 |
|---|---|---|
| 1行ずつ文字列を分割して評価 | トークン化 → 構文解析 → AST → 評価 | 目的（処理系の仕組みの理解）に合わせる |
| 式の括弧が使えない | `( )` でグループ化できる | 4.1 の規則で区別できる |
| 行末コメントで行が無視される | 行末コメントを許す | |
| `$n * -1` が動かない | 単項 `-` を追加 | |
| エラーに行番号がない | 行・列を表示 | |
| 引用符なしの文字列（`@name = dolphin`） | `"..."` で囲む（確定） | Lexer で識別子と区別するため |
| 組み込み関数は出力引数で結果を返す（`arr_len[nums, @len]`） | 戻り値で返す（`@len = arr_len[@nums]`）（確定） | ユーザー定義関数と同じ形にし、式の中で使えるようにする |
| 真偽値は 1 / 0 | `true` / `false`（確定） | JSON との対応 |
| `@`（グローバル）と `$`（ローカル）の 2 種類 | `@` だけ。スコープは宣言の場所で決まる（確定 2026-10-11） | クロージャを入れるため。`@` の個性は残す |
| 最初の代入で宣言 | `:=` で宣言、`=` は代入のみ（確定 2026-10-11） | 外側の変数の書き換えと新規宣言を区別する。タイプミスも検出できる |
| 配列の添字は `@a[0]` | `@a{0}`（確定 2026-10-11） | 関数値の呼び出し `@f[0]` と見分けるため |

## 7. 未決事項

決定済み（2026-10-04）: 文字列は引用符で囲む、組み込み関数は戻り値で返す、真偽値は `true` / `false`。内容は 3〜6 章に反映した。

### 7.1 配列の渡し方（決定済み 2026-10-06）

**参照渡し**に決定。配列とマップは、関数に渡しても変数に代入しても同じものを指す（Python、JavaScript と同じ）。

```
@a = {1, 2}
@b = @a
arr_push[@b, 3]
log[@a]        // {1, 2, 3}
```

理由: 実装が軽く（`Rc<RefCell<…>>` を共有するだけ）、`arr_push` のようにその場で書き換える関数を自然に書ける。

### 7.2 `gameloop`

旧実装では `gameloop ( ... )` がキーワード付きブロックだった。**キーワードにはしない**（2026-10-11）。関数値とイベントループ（8 章）を入れたうえで、`ui` / `canvas` ライブラリが「毎フレーム呼ぶ関数」を受け取る形にする。

## 8. 方向の見直し（2026-10-11）

最終目標は、実用レベルの言語にすること（Yay! API クライアント、デスクトップアプリ、ゲームが書ける）。今の設計に無理に合わせず、土台から見直す。GUI の機能を足す前に、言語の土台を先に変える。

### 8.1 順序

| 順 | 内容 | 状態 |
|---|---|---|
| 1 | 文法の見直し: `$` 廃止、`:=` と `=`、添字 `{ }`（3〜5 章に反映済み） | 確定（2026-10-11） |
| 2 | 関数値とクロージャ（5.8） | 確定（2026-10-11） |
| 3 | エラー処理（8.6）。エラー値を返し、`?` で伝える | 確定（2026-10-11） |
| 4 | 実行モデル（8.3）。インタプリタのスレッド、イベントループ | 方針は確定 |
| 5 | JSON、HTTP、ハッシュ・HMAC | 案 |
| 6 | `ui` ライブラリ（8.4）、`canvas` ライブラリ | 案 |

### 8.2 関数値とクロージャ

5.8 に移した。無名関数は `[` で始まるので、今の文法と衝突しない（式の先頭に `[` が来る場面がない）。

### 8.3 実行モデル（決定済み 2026-10-11）

**Elm 型**: GUI とインタプリタを別のスレッドに置き、メッセージでつなぐ。

```
 メインスレッド          インタプリタのスレッド（大きなスタック）        補助スレッド
 ┌────────────┐  イベント  ┌─────────────────────────────┐  結果   ┌────────────┐
 │ GUI（描画・入力）│ ───────▶ │ イベントループ: 受け取って関数を呼ぶ │ ◀────── │ 通信・タイマー │
 │            │ ◀─────── │ 画面（データ）を作って送る        │ ──────▶ │            │
 └────────────┘  画面     └─────────────────────────────┘  依頼   └────────────┘
```

| 項目 | 内容 | 状態 |
|---|---|---|
| インタプリタ | 1 スレッドのまま。`Rc` を使い続ける。スタックの大きい専用スレッドで動かす | 確定 |
| スレッドをまたぐ値 | データ（数値・文字列・真偽値・配列・マップ）だけ。関数値は持ち出さず、番号で呼ぶ | 確定 |
| メインスレッド | GUI だけを担当する。macOS はメインスレッドでウィンドウのループを動かす必要があるため | 確定 |
| 通信・ファイル | 順番に進む処理は**ブロッキング関数**（`http_get[url]` が結果を返す）で書く。インタプリタのスレッドが待つだけで、画面は固まらない | 確定 |
| ブロッキング中のイベント | 溜めておき、終わってから順に処理する。ロード中の表示は、通信の前に `ui.refresh[]` で先に出す | 案 |
| 同時進行 | コールバック型の関数（`http_get_async[url, @cb]`）を別に用意する。コールバックは結果の値を 1 つ受け取る | 案 |
| `await` | 作らない。VM（段階 6）を作ったときに、コールバック型を下地にして構文だけ足す | 後回し |
| 実行中のエラー | 画面を持つアプリは、落とさずエラーを画面かターミナルに出す | 案 |

後回しの理由: 順番に進む処理はブロッキングで足りる。`await` が必要になるのは、並列取得やループの中の非同期、大量リクエストを捌くサーバーで、すぐには要らない。

### 8.4 `ui` ライブラリ

```
@count := 0
ui.run[[] (
    # ui.column[{
        ui.text["回数: @count"],
        ui.button["増やす", [] ( @count = @count + 1 )]
    }]
)]
```

- 画面を返す関数を書き、状態が変わるたびに呼び直す（宣言的 UI）
- 裏側の描画は、最初は egui（即時モード）で実装する。ユーザーから見えるのは `ui.*` の API だけで、後から差し替えられる
- 日本語表示のため、システムフォントの読み込みか同梱フォントが必要（macroquad も egui も標準フォントに CJK がない）

### 8.5 標準ライブラリの名前（決定済み 2026-10-11）

| 項目 | 内容 | 状態 |
|---|---|---|
| 基本の関数 | 接頭辞で分ける（`str_` `arr_` `map_` `file_` など）。メソッド形（`@s.upper[]`）は採らない。後から足すことはできる | 確定 |
| 名前の付け方 | `型名_動詞`、対象の値を最初の引数にする（`arr_push[a, v]`、`str_split[s, sep]`） | 確定 |
| 大きいライブラリ | `json` `http` `ui` `canvas` `time` などは組み込みモジュールにして、`@ui := import["std:ui"]` で名前空間に入れる。呼び方は通常のモジュールと同じ（`@ui.run[...]`） | 確定 |
| 組み込みモジュールの実装 | `Module` に組み込み関数の表を持たせ、`import["std:..."]` で返す | 案 |
| 名前の衝突 | 組み込み関数と同じ名前の関数は定義できない（今のまま）。1.0 までは、標準ライブラリを足して衝突したら、ユーザー側で直す | 案 |

### 8.6 エラー処理（決定済み 2026-10-11）

エラーを 2 種類に分ける。

| 種類 | 例 | 扱い |
|---|---|---|
| 外の世界の失敗 | ファイルがない、通信できない、JSON が壊れている、`to_num["abc"]` | **エラー値を返す**。呼ぶ側が見て対処する |
| プログラムの間違い | 型が違う、添字が範囲外、未定義の変数、引数の数 | 今までどおり**実行時エラーで止まる** |

```
@text := file_read["a.txt"]
if is_error[@text] (
    log["失敗: ", err_message[@text]]
)

// 失敗したら、その関数からエラーをそのまま返す
load[@path] (
    @text := file_read[@path]?
    @n := to_num[str_trim[@text]]?
    # @n * 2
)
```

| 項目 | 内容 | 状態 |
|---|---|---|
| エラー値 | 新しい型（`エラー`）。種類（`kind`、`"not_found"` のような文字列）とメッセージを持つ | 確定 |
| 失敗しうる関数 | 成功なら通常の値、失敗ならエラー値を返す。`file_read` `file_write` `file_append` `to_num` のほか、これから足す `json_parse` `http_*` など | 確定 |
| 関数 | `is_error[v]`（真偽値）、`err_kind[e]`、`err_message[e]`、`err_new[kind, message]`（自分で作る） | 確定 |
| `?`（後置） | `式?`。値がエラーなら、いまの関数（無名関数を含む）からそのエラーを返す。エラーでなければ、その値になる。関数の外で使ってエラーになったら、実行時エラーで止まる | 確定 |
| 放置の禁止 | 式文の値がエラーなら、実行時エラーにする（`file_write[...]` の失敗に気づかないまま進まないため）。変数に入れるか、`?` を付けるか、`is_error` で見ればよい | 確定 |
| エラー値の誤用 | `if` の条件や演算にエラー値を使ったら、実行時エラー（型が違う場合と同じ） | 確定 |
| 比較 | `==` は種類とメッセージが同じなら true | 案 |
| 表示 | `<エラー not_found: メッセージ>` | 案 |
| コールバック | 非同期関数（`http_get_async[url, @cb]`）は、成功の値かエラー値を 1 つ渡す | 案 |
| 種類の例 | `not_found` `permission` `io` `parse`（文字列や JSON の形式）`network` `timeout` | 案 |
