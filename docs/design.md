# Dolphin 設計メモ

作り直し版（`main`）の要件と言語仕様をまとめる。旧実装（`archive/cpp`）の構文をもとにしている。処理系の構成は [architecture.md](architecture.md) にまとめる。

状態の書き方:

- **確定**: 決まったこと
- **案**: 提案。決めるまで変更してよい
- **未決**: 選択肢だけ挙げて、まだ決めていないこと

---

## 1. 目的と方針

- インタプリタ言語の仕組みを理解するために、処理系を自作する
- シンタックスはユニークにする（`@` 変数、`[ ]` 呼び出し、`( )` ブロック、`#` return）
- 実用は目的ではないが、実際に使っても困らない水準を目指す
- 最終的にバックエンド API とデスクトップアプリを書けるようにする

## 3. 字句（Lexer）

| トークン | 定義 | 例 |
|---|---|---|
| `VAR` | `@` + 識別子。すべての変数（グローバルもローカルも）に使う（2026-10-11 確定。旧 `GLOBAL` / `LOCAL` を統一） | `@score` |
| `IDENT` | 英字か `_` で始まり、英数字と `_` が続く | `add`, `arr_len` |
| `NUMBER` | `数字+ [ "." 数字+ ]` | `10`, `1.5` |
| `STRING` | `"` で囲む。中の `@識別子` は値に展開する。`\"` `\\` `\n` `\t` `\r` `\@` でエスケープ（`\t` `\r` は 2026-10-12 に追加）。`@` の後が識別子でなければただの文字。`$` は特別扱いしない（2026-10-11 確定） | `"Hello, @name!"`, `"$100"` |
| キーワード | `if` `else` `while` `for` `in` `break` `continue` `true` `false` `nil` | `for` `in` `nil` は 2026-10-11 に追加 |
| 記号 | `[ ] ( ) { } , : = := # .` | |
| 演算子 | `+ - * / % == != < <= > >= && \|\| !` | |
| `NEWLINE` | 改行。文の区切り | |

- `//` から行末まではコメント。旧実装と違い、行末コメントも許す（案）
- `[ ]` と `{ }` の中の改行は無視する。長い引数・配列・マップを複数行に書けるようにするため（案）
- `( )` の中の改行は無視しない。ブロック内の文の区切りに使うため

## 4. 文法（EBNF）

表記: `{ x }` は0回以上、`[ x ]` は省略可、`|` は選択、`"x"` は終端記号。

```ebnf
program     = { NEWLINE } { statement terminator } EOF ;
terminator  = NEWLINE { NEWLINE } | EOF ;

(* ---- 文 ---- *)
statement   = func_def
            | if_stmt
            | while_stmt
            | for_stmt
            | return_stmt
            | "break"
            | "continue"
            | assignment
            | expr_stmt ;

assignment  = variable ":=" expression                          (* 宣言 *)
            | variable { "{" expression "}" } "=" expression ;   (* 代入。添字つきは要素の書き換え *)
variable    = VAR ;

func_def    = IDENT "[" [ params ] "]" block ;
params      = VAR { "," VAR } ;

if_stmt     = "if" expression block
              [ { NEWLINE } "else" ( block | if_stmt ) ] ;
while_stmt  = "while" expression block ;
for_stmt    = "for" variable "in" expression block ;
return_stmt = "#" [ expression ] ;
expr_stmt   = expression ;

block       = "(" { NEWLINE } [ statement { NEWLINE { NEWLINE } statement } ] { NEWLINE } ")" ;

(* ---- 式（下ほど優先度が高い） ---- *)
expression  = or_expr ;
or_expr     = and_expr { "||" and_expr } ;
and_expr    = cmp_expr { "&&" cmp_expr } ;
cmp_expr    = add_expr [ ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) add_expr ] ;
add_expr    = mul_expr { ( "+" | "-" ) mul_expr } ;
mul_expr    = unary { ( "*" | "/" | "%" ) unary } ;
unary       = ( "-" | "!" ) unary | postfix ;
postfix     = primary { "{" expression "}" | "[" [ args ] "]" | "." member | "?" } ;
                                                      (* 添字は { }、値の呼び出しは [ ]（2026-10-11 確定） *)
member      = IDENT [ "[" [ args ] "]" ] ;      (* 名前空間の関数呼び出し、または変数の読み取り *)
primary     = NUMBER
            | STRING
            | "true" | "false" | "nil"
            | variable
            | call
            | IDENT                                   (* 関数名だけ = 関数値（5.8） *)
            | lambda
            | array_lit
            | map_lit
            | "(" expression ")" ;

call        = IDENT "[" [ args ] "]" ;
lambda      = "[" [ params ] "]" block ;
args        = expression { "," expression } ;
array_lit   = "{" [ args ] "}" ;
map_lit     = "{" ":" "}"
            | "{" entry { "," entry } "}" ;
entry       = expression ":" expression ;
```

### 4.1 文法上の注意

- **`(` の二重の役割**: `(` はブロックの開始と、式のグループ化の両方に使う。式の途中（二項演算子の後ろを除く）に `(` が来ても式は続かないので、`if @a > 0 (` の `(` はブロックと判定できる。`if (@a + @b) > 0 (` の先頭の `(` は式の始まりなのでグループ化になる
- **関数定義と呼び出しの区別**: どちらも `IDENT [ ... ]` で始まる。`]` の直後が `(` なら定義、それ以外なら呼び出し
- **括弧の役割分担**（2026-10-11 確定）: `[ ]` は呼び出し、`( )` はブロックとグループ化、`{ }` はデータ（配列・マップのリテラルと添字）。関数が値になっても、`@f[1]`（呼び出し）と `@a{1}`（添字）を見た目で区別できる
- **`{` の曖昧さ**: 式の直後の `{` は添字。`[ ]` `{ }` の中は改行を無視するので、`log[@a` と改行して `{1}` と書くと添字に読まれる。文の先頭に配列リテラルを置くときは、前の行と同じ `[ ]` の中に入れない
- **`else` の位置**: 旧実装では `)` の次の行に `else (` を書く。そのため `if` ブロックの後は、改行を読み飛ばして `else` があるか先読みする
- **`else if`**: 旧実装にはない。`else` の後に `if_stmt` を書けるようにして対応する（案）
- **`-` と `!` の単項演算子**: 旧実装にはない（`@x * -1` が動かない原因）。追加する（案）
- **配列とマップの区別**: どちらも `{` で始まる。最初の要素の後に `:` があればマップ、なければ配列。`{}` は空の配列、`{:}` は空のマップ
- **1行に複数の文**: 書けない。文は改行で区切る（旧 docs の `( @py = 472  @vy = 0 )` は不可）（案）

### 4.2 例

```
// 合計を返す
add[$a, $b] (
    # $a + $b
)

@nums := {10, 20, 30}
@i := 0
while @i < 3 (
    if @nums{@i} > 15 (
        log["@i 番目は 15 より大きい"]
    )
    else (
        @nums{@i} = add[@nums{@i}, 100]
    )
    @i = @i + 1
)
```

## 5. 意味論

### 5.1 変数とスコープ

| 項目 | 内容 | 状態 |
|---|---|---|
| `@x` | すべての変数。グローバルかローカルかは、宣言された場所で決まる（字句スコープ）。`$` は廃止 | 確定（2026-10-11） |
| 宣言 | `@x := 式`。いま入っているスコープに新しい変数を作る。同じスコープでの二重宣言はエラー。内側のスコープで同じ名前を宣言すると、外側を隠す | 確定（2026-10-11） |
| 代入 | `@x = 式`。外側を含めて、宣言済みの最も内側の `@x` を書き換える。宣言されていなければ**実行前エラー**（タイプミスを検出する） | 確定（2026-10-11） |
| トップレベルの変数 | そのファイルの変数。ファイル内のどの関数からも読み書きできる（旧 `@` の役目）。ほかのファイルとは別（5.7） | 確定（2026-10-11） |
| 関数内の変数 | 引数と、関数内で `:=` した変数。呼び出しごとに作られる | 確定（2026-10-11） |
| クロージャ | 関数値は、作られたときの外側のスコープの変数を捕まえる（共有する。コピーではない） | 確定（2026-10-11） |
| 未宣言の参照 | 実行前エラー（Resolver が検出する） | 案 |

旧実装との違い: 「最初の代入で宣言される」規則をやめた。クロージャが外側の変数を書き換えるのか、同名の新しい変数を作るのかを区別するため。

### 5.2 関数

| 項目 | 内容 | 状態 |
|---|---|---|
| 定義場所 | トップレベルのみ | 案 |
| 定義前の呼び出し | 実行前に全関数を登録し、定義より前の行から呼べるようにする | 案 |
| 引数 | 値渡し。ただし配列とマップは参照を渡す（7.1）。数が合わなければ実行前にエラー | 案 |
| 戻り値 | `# expr` で返す。`#` なしで終わったら「値なし」 | 案 |
| 関数値 | 関数を変数に入れたり、引数に渡したり、戻り値にしたりできる。5.8 | 確定（2026-10-11） |
| 再帰 | 可能 | 案 |

### 5.3 値と型

| 型 | 例 | 状態 |
|---|---|---|
| 数値 | `10`, `1.5`（内部は double） | 案 |
| 文字列 | `"dolphin"`。`"..."` 内の `@name` は展開される | 確定 |
| 配列 | `{1, 2, 3}` | 案 |
| マップ | `{"name": "Dolphin", "age": 3}`。5.4 | 確定（2026-10-06） |
| モジュール | `import["util.dol"]` の結果。5.7 | 確定（2026-10-11） |
| バイト列 | `str_to_bytes["hi"]` など。変更できない。5.14 | 確定（2026-10-12） |
| 関数 | `[@n] ( # @n + 1 )` や、`add` のような関数名。5.8 | 確定（2026-10-11） |
| 真偽値 | `true` / `false`。比較演算の結果も真偽値 | 確定 |
| 値なし | 戻り値のない関数の結果。`nil` と書ける（確定 2026-10-11）。JSON の `null` に当たる | 確定 |
| エラー | 失敗しうる関数が返すエラー値。種類とメッセージを持つ。8.6 | 確定（2026-10-11） |

旧実装はすべての値を文字列で持ち、計算のたびに数値へ変換していた。作り直し版では値に型を持たせる（案）。

- `if` / `while` の条件が真偽値でない場合は実行時エラーにする（案）
- `+` は数値どうしなら加算、文字列どうしなら連結。数値と文字列の混在は実行時エラー（案）

### 5.4 マップ

| 項目 | 内容 | 状態 |
|---|---|---|
| キー | 文字列のみ。リテラルのキーには式も書ける（`{@k: 1}`）が、値が文字列でなければ実行時エラー | 確定（2026-10-06） |
| 読み取り | `@m{"key"}`。キーがなければ実行時エラー。あるかどうかは `map_has` で調べる | 案 |
| 書き込み | `@m{"key"} = v`。キーがなければ追加、あれば上書き | 案 |
| 順序 | 追加した順を保つ（表示や将来の JSON 出力で順序が変わらないように） | 案 |
| 比較 | `==` はキーと値の組が同じなら true。順序は見ない | 案 |
| 表示 | `{"name": "Dolphin", "age": 3}`。空は `{:}`。配列やマップの中の文字列は `"` で囲む | 案 |
| 組み込み関数 | `map_len` `map_keys`（キーの配列）`map_has` `map_remove`（取り除いた値を返す） | 案 |

### 5.5 組み込み関数

引数の型や数が違うときは実行時エラー。文字列の位置と長さはすべて文字単位（`str_len["イルカ"]` は 3）。

| 分類 | 関数 | 内容 |
|---|---|---|
| 入出力 | `log[...]` | 引数を空白区切りで出力して改行 |
| | `input[]` | 1 行読んで文字列で返す（末尾の改行は除く） |
| ファイル | `file_read[path]` | ファイル全体を文字列で返す。読めなければエラー値（`not_found` `permission` `io`。UTF-8 として読めなければ `parse`） |
| | `file_write[path, s]` | 文字列を書き込む。なければ作り、あれば置き換える |
| | `file_append[path, s]` | 文字列を末尾に足す。なければ作る |
| | `file_exists[path]` | ファイルかディレクトリがあるか（真偽値） |
| 文字列 | `str_len[s]` | 文字数 |
| | `str_concat[...]` | 値を文字列にしてつなげる |
| | `str_upper[s]` / `str_lower[s]` / `str_trim[s]` | 大文字・小文字・前後の空白を除く |
| | `str_contains[s, sub]` | 含むか（真偽値） |
| | `str_find[s, sub]` | 最初の位置。なければ -1 |
| | `str_replace[s, from, to]` | すべて置き換える |
| | `str_split[s, sep]` | 配列に分ける。`sep` が `""` なら 1 文字ずつ |
| | `str_join[arr, sep]` | 配列の要素をつなげる |
| | `str_sub[s, start, end]` | `start` から `end` の手前まで |
| エラー | `is_error[v]` / `err_kind[e]` / `err_message[e]` / `err_new[kind, message]` | エラー値か調べる・種類・メッセージ・自分で作る（8.6） |
| 変換 | `to_str[v]` | `log` と同じ表示の文字列 |
| | `to_num[v]` | 文字列を数値に（前後の空白は無視）。変換できなければ `parse` のエラー値 |
| 配列 | `arr_len[a]` / `arr_push[a, v]` / `arr_pop[a]` | 長さ・末尾に追加・末尾を取り出す |
| | `range[a, b]` | `a` 以上 `b` 未満の整数の配列。`a >= b` なら空。1000 万要素まで |
| | `arr_map[a, f]` | 各要素に `f` を適用した新しい配列 |
| | `arr_filter[a, f]` | `f` が `true` を返した要素だけの新しい配列（`f` は真偽値を返す） |
| | `arr_each[a, f]` | 各要素に `f` を適用する（戻り値は使わない） |
| マップ | `map_len[m]` / `map_keys[m]` / `map_has[m, k]` / `map_remove[m, k]` | 5.4 |
| 数学 | `abs` `floor` `ceil` `round` `sqrt` | 引数 1 つ。`round` は 0.5 を 0 から遠いほうへ丸める |
| | `pow[a, b]` / `min[...]` / `max[...]` | べき乗・最小・最大 |
| | `random[]` / `random_int[min, max]` | 0 以上 1 未満 / `min` 以上 `max` 以下の整数 |

ファイル関数のパスは、実行したときのカレントディレクトリからの相対パス（`import` は呼び出したファイルのあるディレクトリから引くので、基準が違う）。読み書きに失敗したらエラー値（`file_write` `file_append` は、成功なら `nil`）。文字コードは UTF-8 のみ。削除・一覧・ディレクトリ作成は未定（案）。

### 5.6 制御

| 項目 | 内容 | 状態 |
|---|---|---|
| `if` / `while` の条件 | 真偽値のみ。それ以外は実行時エラー | 案 |
| `for` | `for @x in 式 ( … )`。式は配列で、要素を順に `@x` に入れて本体を実行する。配列でなければ実行時エラー。本体は繰り返しごとに新しいスコープ（`@x` も繰り返しごとに別の変数）。回し始めた時点の配列の要素を使う（途中で書き換えても回す対象は変わらない） | 確定（2026-10-11） |
| マップ・回数指定 | マップは `for @k in map_keys[@m]`、回数は `for @i in range[0, 10]`（`range` は配列を返す。終わりの値は含まない） | 確定（2026-10-11） |
| `break` | いちばん内側の `while` / `for` を抜ける | 確定（2026-10-06） |
| `continue` | いちばん内側の `while` / `for` の次の繰り返しへ進む | 確定（2026-10-06） |
| 使える場所 | `break` / `continue` は `while` / `for` の中だけ。関数の中から外側のループは抜けられない（実行前にエラー） | 確定（2026-10-06） |
| 複合代入 | `+=` などは作らない。`@i = @i + 1` と書く | 確定（2026-10-11） |

### 5.7 モジュール（import）

```
@u = import["util.dol"]
log[@u.add[1, 2]]     // 関数を呼ぶ
log[@u.version]       // util.dol の @version を読む
```

| 項目 | 内容 | 状態 |
|---|---|---|
| 書き方 | `import[path]` はファイルを実行してモジュールを返す組み込み関数。結果を `@` 変数に入れて使う | 確定（2026-10-11） |
| 名前空間 | 名前空間つき（Python の `import util` に近い）。呼び出しは `@u.add[1, 2]` | 確定（2026-10-11） |
| `@` 変数のスコープ | ファイルごとに別。ほかのファイルの `@x` とはぶつからない。そのファイルの関数からは今までどおり読み書きできる | 確定（2026-10-11） |
| 外からの変数アクセス | `@u.name` で読める。`@u.name = v` のように外から書くのは構文エラー。書き換えたいときは、そのファイルに setter 関数を書く | 確定（2026-10-11） |
| 公開の範囲 | 絞る仕組みはなし。関数も `@` 変数も全部見える | 確定（2026-10-11） |
| 同じファイルを 2 回 import | 2 回目は 1 回目の結果を使う。実行は 1 回だけ（Python と同じ） | 確定（2026-10-11） |
| パスの基準 | import するファイルのあるディレクトリ。REPL ではカレントディレクトリ | 案 |
| 循環 import | 実行時エラー | 案 |
| 組み込み関数 | 名前空間をまたいでそのまま使える（`@u.log[...]` とは書かない） | 案 |
| 存在しない名前 | `@u.nope` や `@u.nope[]` は実行時エラー | 案 |
| 表示 | `<module "util.dol">`。名前は本体のあるディレクトリからの相対パス | 案 |
| `.名前[...]` | 常に関数呼び出し。モジュールの配列の要素は `@u.items{0}` で読める（添字が `{ }` になったため） | 案 |
| 文字列の中 | `"@u.name"` は `@u` だけが展開される（`.name` はそのまま文字）。モジュールの変数は `@u.name` を式として書く | 案 |
| エラーの表示 | import したファイルで起きたエラーは、そのファイルの行を引用し、import した位置を呼び出し履歴に載せる | 案 |

### 5.8 関数値とクロージャ

```
add[@a, @b] ( # @a + @b )              // 名前つきの定義（これまでどおり）
@f := add                              // 関数名だけを書くと、関数値になる
@inc := [@n] ( # @n + 1 )              // 無名関数
log[@f[1, 2], @inc[1]]                 // 変数の関数値は @f[...] で呼ぶ

make_counter[] (
    @n := 0
    # [] (
        @n = @n + 1
        # @n
    )
)
@c := make_counter[]
log[@c[], @c[]]                        // 1 2（@n は呼び出しをまたいで共有される）
log[arr_map[{1, 2, 3}, [@x] ( # @x * 2 )]]
```

| 項目 | 内容 | 状態 |
|---|---|---|
| 無名関数 | `[ 引数 ] ( 本体 )` は式。引数は `@` 変数。本体は関数と同じ（`#` で返す。改行で文を区切る） | 確定（2026-10-11） |
| 関数名 | `add` のように `[` を付けずに書くと関数値。組み込み関数（`log` など）も同じ。`import` は関数値にできない | 確定（2026-10-11） |
| 呼び出し | `式[ 引数 ]`。`IDENT[...]` は名前で呼ぶ、それ以外（`@f[1]`、`@make[][2]`、`@u.f` の結果など）は値を呼ぶ。`[ ]` は呼び出し専用で、添字は `{ }` | 確定（2026-10-11） |
| 捕まえるもの | 関数値は、作られた場所のスコープを参照で捕まえる（コピーしない）。外側の変数を書き換えると、関数値からも見える | 確定（2026-10-11） |
| ループの中で作る | `while` の本体は繰り返しごとに新しいスコープなので、本体で `:=` した変数は繰り返しごとに別になる | 確定（2026-10-11） |
| `break` `continue` | 無名関数の中からは、外側の `while` を抜けられない（関数と同じ） | 確定（2026-10-11） |
| 比較 | `==` は、同じ定義を同じスコープから取り出した関数値なら true（`@f == add`）。同じ無名関数でも、呼び出しごとに作られたものは別の値 | 案 |
| 表示 | `<関数 add>` / `<関数>`（無名）/ `<組み込み関数 log>` | 案 |
| 引数の数 | 呼び出すときに検査する（合わなければ実行時エラー） | 案 |
| モジュールの関数 | `@u.add`（`[` なし）は、`@u` の変数 `add` がなければ関数 `add` を関数値として返す | 案 |
| 組み込み関数からの呼び出し | `arr_map` などが関数値を呼ぶ。中で起きたエラーは、呼び出し履歴つきで報告する | 案 |
| メモリ | 関数値は自分を作ったスコープを参照するので、自分自身を持つ変数に入れると循環する。`Rc` では解放されない（`@a` が自分を含む配列と同じ扱い。architecture.md 6 章） | 案 |

### 5.11 HTTP クライアント（`std:http`）

```
@http := import["std:http"]
@json := import["std:json"]

@r := @http.get["https://example.com/api/users", {"headers": {"Authorization": "Bearer abc"}, "query": {"page": 2}, "timeout": 10}]?
log[@r{"status"}, @r{"ok"}, @r{"headers"}{"content-type"}]
@users := @json.parse[@r{"body"}]?

@login := @http.post["https://example.com/api/login", {"json": {"user": "a", "pass": "b"}}]?
```

| 関数 | 内容 |
|---|---|
| `request[options]` | 全部入り。`options` に `url` と（省略すると `"GET"` の）`method` を書く |
| `get[url]` `get[url, options]` | `GET` |
| `post[url, options]` `put[url, options]` `delete[url, options]` | それぞれの method。`options` は省略できる（`delete[url]`） |

| `options`（マップ）のキー | 内容 |
|---|---|
| `url` `method` | `request` だけで使う。`get` などで指定すると実行時エラー |
| `headers` | マップ。値は文字列 |
| `query` | マップ。値は文字列・数値・真偽値。パーセントエンコードして URL に付ける（URL にすでに `?` があれば `&` でつなぐ） |
| `body` | 文字列。そのまま送る |
| `json` | 値。JSON にして送り、`Content-Type: application/json` を付ける（`headers` で指定していれば、そちらが優先）。`body` とは同時に使えない |
| `timeout` | 秒（小数も可）。接続から本文を読み終えるまでの全体。省略は 30 |
| `redirects` | 追いかけるリダイレクトの回数。省略は 5。`0` なら、リダイレクトの応答（`301` など）がそのまま返る |

| 項目 | 内容 | 状態 |
|---|---|---|
| 戻り値 | マップ `{"status": 200, "ok": true, "headers": {...}, "body": "..."}`。`ok` は 200〜299。ヘッダー名は小文字で、同じ名前が複数あれば `, ` でつなぐ | 確定（2026-10-12） |
| `404` や `500` | エラーにしない。普通のレスポンスとして返す（API のエラー本文を読めるように） | 確定（2026-10-12） |
| 通信の失敗 | エラー値を返す。種類は `timeout`、`url`（URL が正しくない）、`request`（ヘッダーなどが正しくない）、`too_large`（本文が 32 MB を超えた）、`parse`（本文が UTF-8 ではない）、`network`（そのほか。名前が引けない、接続できない、TLS、リダイレクトの回りすぎなど） | 確定（2026-10-12） |
| 本文 | 送受信とも文字列（UTF-8）だけ。バイナリは、バイト列の型を作るときに足す | 確定（2026-10-12） |
| オプションの間違い | 知らないキー、型の間違い、`json` と `body` の同時指定などは、プログラムの間違いとして実行時エラー | 案 |
| User-Agent | `dolphin/<バージョン>`。`headers` で上書きできる | 案 |
| 圧縮 | `gzip` の応答は自動で展開する | 案 |
| 接続 | リクエストごとに接続する（使い回さない）。クッキーは扱わない | 案 |
| ブロッキング | インタプリタのスレッドが待つ（8.3）。非同期版は、実行モデルの実装と一緒に作る | 確定 |
| ビルド | `http` feature（既定で有効）。TLS は rustls。外した版で `import["std:http"]` すると、含まれていないことを案内する | 確定（2026-10-12） |

#### `std:math`（`import["std:math"]`）

定数と、使用頻度の低い関数は、名前空間に入れる。基本の `abs` `floor` `ceil` `round` `sqrt` `pow` `min` `max` `random` は今までどおり（接頭辞なしの関数）。

| 名前 | 内容 |
|---|---|
| `pi` `e` `inf` `nan`（変数。`@m.pi`） | 定数。`inf` は無限大、`nan` は非数 |
| `sin` `cos` `tan` `asin` `acos` `atan` `atan2[y, x]` | 三角関数（ラジアン） |
| `exp` `ln` `log10` `log2` `hypot[a, b]` | 指数・対数 |
| `is_nan[x]` / `is_finite[x]` | 判定 |

組み込みモジュールが変数（定数）を持てるようにする（5.9 の「変数は持たない」を改める）。

`std:math` の関数は IEEE 754 に従い、定義できない入力には `nan` や `inf` を返す（`@m.ln[-1]` は `nan`、`@m.ln[0]` は `-inf`）。基本の `sqrt` が負の数でエラーになるのとは別の方針（`sqrt` は今までどおり）。

#### `std:path`

パスの文字列を、ファイルに触れずに組み立てる・分解する。入力は、そのシステムの区切り（Windows は `\` と `/`）を受け付け、**出力は常に `/` 区切り**（Windows も `/` を受け付けるので、スクリプトがシステムによらず同じ結果になる）。

| 名前 | 内容 |
|---|---|
| `join[a, b, ...]` | つなげる（1 個以上の文字列。あとの部分が絶対パスなら、それ以前を捨てる） |
| `dirname[p]` / `basename[p]` | ディレクトリ部分・最後の名前（`dirname["a"]` は `""`、`basename["a/b/"]` は `"b"`） |
| `stem[p]` / `ext[p]` | 拡張子を除いた最後の名前・拡張子（`"."` を含む。`ext["a.tar.gz"]` は `".gz"`、なければ `""`） |
| `normalize[p]` | `.` と `..` を字面だけで整理する（ファイルは見ない） |
| `is_absolute[p]` | 絶対パスか |
| `absolute[p]` | カレントディレクトリを基準に絶対パスにして `normalize` する |
| `sep`（変数） | `"/"` |

#### `std:os`

| 名前 | 内容 |

| `platform[]` | `"windows"` `"macos"` `"linux"` など |
| `temp_dir[]` | 一時ファイルを置くディレクトリ |

#### `std:time`

時刻は **Unix 時刻（1970-01-01 00:00 UTC からの秒。小数）** の数値で表す。時差は「UTC からの分」（日本は `540`）で指定する。省略は UTC。

| 名前 | 内容 |
|---|---|
| `now[]` | 現在時刻（ミリ秒の精度） |
| `monotonic[]` | 経過時間の計測用。起点は不定で、戻らない（秒） |
| `sleep[seconds]` | 待つ（インタプリタのスレッドが止まる）。負の数は実行時エラー |
| `date[ts]` `date[ts, offset]` | マップ `{"year", "month", "day", "hour", "minute", "second", "millisecond", "weekday", "yday"}`。`weekday` は 0（日曜）〜6、`yday` は 1 月 1 日が 1 |
| `timestamp[fields]` `timestamp[fields, offset]` | `date` の逆。`year` `month` `day` は必須、`hour` `minute` `second` `millisecond` は省略すると 0。範囲外（13 月、2 月 30 日など）はエラー値（`parse`）。`date` の結果をそのまま渡せるよう、`weekday` と `yday` は受け取って無視する。知らない項目は実行時エラー |
| `format[ts, pattern]` `format[ts, pattern, offset]` | 書式にして文字列。`%Y`（年）`%m` `%d` `%H` `%M` `%S` `%f`（ミリ秒 3 桁）`%y` `%e`（空白埋めの日）`%j`（年内の日）`%a` `%A`（曜日の英語名）`%b` `%B`（月の英語名）`%p`（AM/PM）`%I`（12 時間）`%z`（`+0900`）`%%`。ほかの `%` は実行時エラー |
| `parse[s, pattern]` | `format` と同じ書式で読む。`%z` があればその時差、なければ UTC として Unix 時刻にする。合わなければエラー値（`parse`）。`%a` `%A` `%b` `%B` は英語の名前（大文字小文字は区別しない） |
| `iso[ts]` `iso[ts, offset]` | RFC 3339 の文字列（`2026-10-12T10:00:00.500Z`、時差があれば `+09:00`）。ミリ秒が 0 なら小数は省く |
| `parse_iso[s]` | RFC 3339 を読む（`Z` か `±hh:mm`、小数秒は省略可）。合わなければエラー値（`parse`） |

| 項目 | 内容 | 状態 |
|---|---|---|
| 暦 | グレゴリオ暦（紀元前も含め、プロレプティック）。うるう秒は扱わない | 案 |
| 範囲 | 年は 1〜9999 | 案 |
| システムの時差 | 今回は扱わない（`offset` を自分で渡す）。システムの時差を引く関数は、OS の API が要るので後で足す | 確定 |
| 名前の衝突 | `file_*` は基本の関数なので、接頭辞を持つ（`file_list` など） | 確定 |

### 5.14 バイト列と暗号（v0.13.0、確定 2026-10-12）

#### バイト列の型

| 項目 | 内容 |
|---|---|
| 型 | `bytes`（`type_of` は `"bytes"`）。0〜255 の並び。**変更できない**（文字列と同じ。ハッシュや比較の安全のため）。リテラルはなく、関数で作る |
| 作る | `str_to_bytes[s]`（UTF-8）、`bytes_from_arr[a]`（0〜255 の整数の配列）、`bytes_new[n]`（0 で埋めた `n` バイト）、`bytes_concat[a, b]` |
| 読む | `bytes_len[b]`、`@b{i}`（`i` 番目の値。範囲外は実行時エラー）、`bytes_slice[b, start, end]`（`str_sub` と同じ範囲の規則）、`bytes_to_arr[b]`、`bytes_find[b, sub]`（位置。なければ `-1`） |
| 文字列にする | `bytes_to_str[b]`。UTF-8 でなければ `parse` のエラー値 |
| 比較 | `==` は中身が同じなら true |
| 表示 | `<bytes 68656c6c6f>`（16 進数。33 バイト以上は先頭 32 バイトの後に `…（N バイト）`） |
| 書き込み | `@b{i} = v` は実行時エラー。`for` で回せるのは配列だけなので、`bytes_to_arr` を使う |
| JSON | バイト列は JSON にできない（実行時エラー）。`std:encoding` で base64 などにして渡す |

#### ほかの関数での使い方

| 場所 | 内容 |
|---|---|
| ファイル | `file_read_bytes[path]`、`file_write_bytes[path, b]`、`file_append_bytes[path, b]`。失敗はエラー値（`file_read` と同じ） |
| `std:http` | `options` の `body` はバイト列も渡せる。`options` に `"as": "bytes"` を足すと、レスポンスの `body` がバイト列になる（省略は `"text"`。UTF-8 でない本文でもエラーにならない） |
| `std:os` の `run` | `stdin` にバイト列を渡せる。`options` に `"as": "bytes"` を足すと、`stdout` と `stderr` がバイト列になる |

#### `std:encoding`

引数にバイト列と文字列（UTF-8 として扱う）の両方を受け付ける。

| 関数 | 内容 |
|---|---|
| `base64_encode[data]` / `base64_decode[s]` | 標準の base64（`+` `/`、`=` の詰め物あり）。`decode` は空白と改行を無視する。正しくなければ `parse` のエラー値。`decode` の結果はバイト列 |
| `base64url_encode[data]` / `base64url_decode[s]` | URL 向け（`-` `_`）。`encode` は詰め物なし。`decode` は詰め物の有無どちらも受け付ける |
| `hex_encode[data]` / `hex_decode[s]` | 16 進数（小文字）。`decode` は大文字小文字を区別せず、奇数桁や正しくない文字は `parse` のエラー値 |
| `url_encode[s]` / `url_decode[s]` | URL の部品のパーセントエンコード（英数字と `-` `.` `_` `~` 以外を `%XX` に）。`decode` は `+` を空白にしない。UTF-8 にならなければ `parse` のエラー値 |

#### `std:crypto`

`crypto` feature（既定で有効）。ハッシュ・HMAC・乱数は `ring`、md5 は `md-5` を使う（暗号は自前で書かない）。

| 関数 | 内容 |
|---|---|
| `hash[algorithm, data]` | ダイジェスト（バイト列）。`algorithm` は `"sha1"` `"sha256"` `"sha384"` `"sha512"` `"md5"`。`sha1` と `md5` は壊れた方式なので、互換のためだけに使う（署名やパスワードには使わない） |
| `hmac[algorithm, key, data]` | HMAC（バイト列）。`algorithm` は `"sha1"` `"sha256"` `"sha384"` `"sha512"`（`md5` は不可） |
| `random_bytes[n]` | OS の乱数で作った `n` バイト（0〜65536） |
| `uuid[]` | UUID v4（`"xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx"` の文字列） |
| `equals[a, b]` | 2 つのバイト列（か文字列）が同じか。時間が中身によらない（HMAC の検証用） |

16 進数にしたいときは `@enc.hex_encode[@crypto.hash["sha256", "abc"]]` のように組み合わせる。

### 5.15 メモリ回収（v0.15.0、確定 2026-10-12）

値の寿命は `Rc`（参照カウント）で管理している。これだけだと、**循環した参照は解放されない**。たとえば関数の中で名前つきの関数を定義すると、スコープが関数値を持ち、関数値がスコープを持つ循環ができる。呼び出しのたびに漏れるので、長く動くサーバーでは問題になる。そこで、`Rc` は残したまま、循環だけを見つけて壊す**循環回収器**を足す。

| 項目 | 内容 | 状態 |
|---|---|---|
| 方式 | 参照カウントを使う試行削除（Bacon–Rajan 型）。ルートの一覧は要らない | 確定 |
| 対象 | 配列、マップ、スコープ（`Env`）、関数値（`Closure`）。作ったときに登録簿へ弱参照で登録する | 確定 |
| 見つけ方 | 登録簿の全体について、「各対象が数えている参照のうち、登録簿の対象どうしの参照」を引く。引いても参照が残る対象は、外（Rust のスタック、モジュールなど）から持たれているので生きている。そこから辿れるものも生きている。残りは、外から届かない循環（ごみ） | 確定 |
| 壊し方 | ごみの配列・マップ・スコープの中身を空にする（循環は必ずどれかを通る）。あとは `Rc` が解放する | 確定 |
| 動かす時期 | 前回の回収から作った対象が一定数（既定 10000、生き残りが多ければその 2 倍まで増やす）を超えたとき、関数呼び出しの入口、ループの 1 周の先頭、サーバーのリクエストの合間に調べる | 確定 |
| 実行中の安全 | 外から持たれている値は、実行中の変数も含めてすべて「生きている」と見なす。借用中（`RefCell` を借りている最中）の対象も生きている扱い。したがって、いつ動かしても実行中の値を壊さない | 確定 |
| 関数 | `gc_collect[]`: すぐに回収し、回収した対象（配列・マップ・スコープ）の数を返す。テストと調整用 | 確定 |
| 保証しないこと | 解放の順序、回収の時期。デストラクタ（終了処理）は作らないので、順序は見えない | 確定 |
| 外部クレート | 使わない（コア言語の方針） | 確定 |

### 5.16 HTTP サーバー（v0.16.0、確定 2026-10-12）

`std:http`（`http` feature）に `serve` を足す。クライアントと同じモジュールに置く。

```
@http := import["std:http"]
@json := import["std:json"]

@http.serve[8080, [@req] (
    if @req{"path"} == "/hello" (
        # {"json": {"message": "hello", "q": @req{"query"}}}
    )
    # {"status": 404, "body": "not found"}
)]?
```

| 関数 | 内容 |
|---|---|
| `serve[port, handler]` | `127.0.0.1` で待ち受ける。`handler` はリクエストのマップを 1 つ受け取る関数 |
| `serve[options, handler]` | `options` は `{"port": 8080, "host": "0.0.0.0", "max_body": 1048576}`（`port` 以外は省略できる） |

`serve` は、止められるまで戻らない（Ctrl+C、`os.exit`）。ポートを開けないなど、始められなかったときはエラー値（種類 `network`）を返す。

#### リクエスト（ハンドラの引数。マップ）

| キー | 内容 |
|---|---|
| `method` | `"GET"` `"POST"` など（大文字） |
| `path` | クエリを除いたパス。パーセントデコードしてある（`/a%20b` → `/a b`） |
| `query` | マップ。値は文字列（同じ名前が複数あれば最後のもの）。パーセントデコード済み |
| `headers` | マップ。名前は小文字、同じ名前が複数あれば `, ` でつなぐ（クライアントの応答と同じ） |
| `body` | 文字列。UTF-8 でなければ `nil` |
| `raw` | バイト列。本文そのまま（なければ空） |
| `remote` | 相手の IP アドレスの文字列 |

#### レスポンス（ハンドラの戻り値）

| 戻り値 | 内容 |
|---|---|
| マップ | `status`（省略は `200`）、`headers`（マップ。値は文字列）、`body`（文字列かバイト列。省略は空）、`json`（値。JSON にして本文にし、`Content-Type: application/json` を付ける。`body` と同時には使えない） |
| 文字列 | `{"body": 文字列}` と同じ（`200`） |

- 文字列の本文の `Content-Type` の既定は `text/plain; charset=utf-8`、バイト列は `application/octet-stream`。`headers` に書けば、そちらが優先。`Content-Length` は自動
- ハンドラが実行時エラーで止まったとき、エラー値や形の違う値を返したときは、相手に `500`（本文 `Internal Server Error`）を返し、メッセージを標準エラーに出して、**サーバーは続ける**（8.3）
- 本文が `max_body`（既定 10 MB）を超えたら、ハンドラを呼ばずに `413`。HTTP として読めなければ `400`

#### 実行の仕組み（8.3 の Elm 型）

| 項目 | 内容 | 状態 |
|---|---|---|
| スレッド | 接続の受け付けと HTTP の解析・応答の書き込みは補助スレッド（接続ごとに 1 つ）。解析済みのデータ（リクエストのマップの元）だけをインタプリタのスレッドに送り、戻ってきた応答データを書く。関数値や `Rc` はスレッドをまたがない | 確定 |
| ハンドラ | インタプリタのスレッドで、**1 つずつ順番に**呼ぶ。ハンドラの中でブロッキングの通信（`http.get` など）をすると、その間ほかのリクエストは待つ | 確定 |
| 回収 | リクエストの合間に循環回収器（5.15）を動かす | 確定 |
| プロトコル | HTTP/1.1。keep-alive、`Content-Length` と `chunked` の本文、`Expect: 100-continue`。HTTP/2 と TLS は扱わない（TLS はリバースプロキシに任せる）。HTTP の解析は自前で書く（外部クレートなし） | 確定 |
| 制限 | ヘッダー全体 64 KB、読み込みの無通信 30 秒で切る、同時接続 256 まで | 案 |
| 後回し | WebSocket とアップグレード、静的ファイルの配信、ルーター、ミドルウェア（言語側で書ける。書き心地は E で） | 後回し |

### 5.17 開発の道具（v0.17.0、確定 2026-10-12）

`dolphin fmt` は 5.18（v0.18.0）に分けた。

#### 組み込み関数（接頭辞なし）

| 関数 | 内容 |
|---|---|
| `assert[cond]` `assert[cond, message]` | `cond`（真偽値）が `false` なら実行時エラー（`message` があればそれが、なければ「assert に失敗しました」がメッセージ）。真偽値以外は型の間違いで実行時エラー |
| `assert_eq[actual, expected]` `assert_eq[actual, expected, message]` | `==` と同じ規則で比べ、違えば実行時エラー。メッセージに両方の値（文字列は `"` つき）を出す |
| `dbg[value]` | 値を `[dbg] 値` の形で**標準エラー**に出し、その値をそのまま返す（式の途中に挟める）。`log` の出力と混ざらない |

`assert` の失敗はプログラムの間違い（8.6）なので、エラー値ではなく実行時エラー。`?` では拾えない。

#### `dolphin check <file>...`

実行せずに、字句・構文・Resolver（5.2 の事前検査）だけを行う。エラーは実行時と同じ形で出す。すべて問題なければ何も出さず終了コード 0、1 つでもあれば 1。`import` するファイルは見ない（実行時に読むため）。

#### `dolphin test [path...]`

| 項目 | 内容 | 状態 |
|---|---|---|
| 対象 | `path` はファイルかディレクトリ（省略は `.`）。ディレクトリは再帰して、名前が `_test.dol` で終わるファイルを集め、名前順に実行する。ファイルを直接渡せば、名前によらず実行する | 確定 |
| テストの書き方 | ファイルの中の、引数 0 個で名前が `test_` で始まる関数が 1 つ 1 つのテスト。定義の順に実行する | 確定 |
| 実行 | ファイルごとに新しい実行環境を作り、まずファイルの本体（トップレベル）を実行してから、テスト関数を順に呼ぶ。トップレベルの変数は、同じファイルのテストの間で共有される（準備に使える）。テストが実行時エラーで止まれば、そのテストの失敗 | 確定 |
| 出力 | ファイルごとに、テストの名前の前に `ok` か `FAIL` をつけて並べる。失敗したテストの直後に、エラー（位置・呼び出し履歴つき）を出す。`log` などの出力は、失敗したファイルのぶんだけ、そのファイルの結果のあとに出す。最後に `N 件成功、M 件失敗` | 確定 |
| 終了コード | すべて成功なら 0、失敗か、ファイルの本体のエラーがあれば 1。テストが 1 つも見つからなければ、その旨を出して 1 | 確定 |
| `os.exit` | テストの中で呼ばれたら、そのファイルの残りのテストは実行せず、失敗として数える | 案 |

```
// math_test.dol
test_add[] (
    assert_eq[1 + 2, 3]
)
test_div[] (
    assert[10 / 4 == 2.5, "割り算は小数になる"]
)
```

### 5.18 `dolphin fmt`（v0.18.0、確定 2026-10-12）

```
dolphin fmt <file.dol>...            ファイルを整形して書き戻す（変えたファイル名を出す）
dolphin fmt --check <file.dol>...    書き換えず、整形が必要なファイルの名前を出す。あれば終了コード 1
dolphin fmt --stdout <file.dol>      整形した結果を標準出力に出す（1 ファイル）
```

**トークン単位の整形**にする。構文木を作り直して印字すると、コメントと、書き手が決めた改行の位置を保つのが難しい。そこで、ソースを字句に分け、**空白と字下げだけ**を決め直す。字句の並びは変えない。

| 項目 | 規則 | 状態 |
|---|---|---|
| 字下げ | 空白 4 つ。開いている括弧（`(` `[` `{`）の**行の数**だけ下げる（1 行に括弧を複数開いても 1 段）。行頭が閉じ括弧なら、その分を先に戻す | 確定 |
| 字句の間の空白 | 二項演算子・`=`・`:=` の前後、`,` と `:`（マップ）の後、キーワードの後、`#` の後に 1 つ。ブロックの `(` の前に 1 つ。括弧の内側、`,` `:` `.` `?` の前、呼び出し `f[` と添字 `@a{` の前、単項の `-` `!` の後には入れない。`{:}` は詰める | 確定 |
| 改行 | 書き手の改行は動かさない（`else` の位置も、複数行に書いた配列・引数もそのまま）。行末の空白は消す | 確定 |
| 空行 | 連続する空行は 1 つにする。ファイルの先頭・末尾、開き括弧の直後、閉じ括弧の直前の空行は消す | 確定 |
| コメント | 中身はそのまま。行末コメントの前は空白 1 つ。単独の行のコメントは、その位置の字下げに合わせる | 確定 |
| 文字列・数値 | そのまま（`"a  b"` や `1.50` を書き換えない） | 確定 |
| 改行コード | 元のファイルが `\r\n` を含めば `\r\n`、なければ `\n`。末尾は改行 1 つ | 確定 |
| 安全の確認 | 整形の前後で字句の並びが同じことを確かめる。違ったら書き換えずに内部エラーとして報告する。構文エラーのあるファイルは整形せず、そのエラーを出す | 確定 |
| 幅の折り返し | しない | 確定 |
| 冪等 | 整形済みのものをもう一度整形しても変わらない | 確定 |

ファイルの中で、組み込み関数と同じ名前の関数を定義できる。そのファイルの中では、定義した関数が組み込み関数より優先される（隠した組み込み関数は、そのファイルでは呼べない）。ほかのファイル（`import` したファイルと、組み込みモジュール）には影響しない。`import` だけは定義できない。

#### `@m.key`（v0.21.0）

マップ `@m` に対して、`@m.key` は `@m{"key"}` と同じ（読み取りも代入も）。`key` は識別子の形のキーだけ。連ねて書ける（`@cfg.db.port`、`@a.b{0}.c = 1`）。キーがなければ `{ }` の添字と同じ実行時エラー。値が関数なら `@m.handler[1]` で呼べる。モジュールの `@u.name` は今までどおり（`@` 変数がモジュールかマップかは実行時に決まる）。モジュールの変数への代入は実行時エラー。

#### 条件式（v0.22.0）

```
@sign := if @n > 0 ( "正" ) else if @n < 0 ( "負" ) else ( "零" )
```

式の中で `if 条件 ( 式 ) else ( 式 )`（`fmt` が整える括弧の内側の空白に合わせて、`( 式 )` と書く）。`else` は省略できない。条件は真偽値。文の先頭の `if` は今までどおり文（式として使いたいときは `@x := if …` のように、先頭以外に置く）。

#### 引数の既定値（v0.23.0）

```
greet[@name, @greeting = "こんにちは"] ( … )
```

`@name = 式` で既定値。既定値のない引数より後ろにだけ書ける。呼ぶたびに、関数のスコープで、前の引数の値が入った状態で評価する（`[@a, @b = @a * 2]`）。引数の数は「必須の数以上、全部の数以下」。無名関数も同じ。

#### 可変長引数と展開（v0.24.0）

```
sum[@first, ...@rest] ( … )        // @rest は残りの引数の配列（空もありうる）
log[...@items]                     // 配列を引数に展開して呼ぶ
@all := {0, ...@a, ...@b}          // 配列リテラルに展開する
```

`...@名前` は最後の引数にだけ書ける（既定値のある引数のあとでもよい）。`...式` は、呼び出しの引数と配列リテラルの中に書け、配列でなければ実行時エラー。組み込み関数の呼び出しにも使える。展開があると、引数の数の検査は実行時になる。

#### 文字列の式展開と生の文字列（v0.25.0）

| 書き方 | 内容 |
|---|---|
| `"@{a + b}"` | `@{ 式 }` の式の値を文字列にして入れる（`@名前` は今までどおり）。式の中に文字列や `{ }` を書いてよい。文字としての `@{` は `\@{` |
| `r"C:\path"` | 生の文字列。エスケープも展開もしない。`"` は含められない |
| `r#"…"…"#` | `#` を何個か挟むと `"` も含められる（`"#` のところで終わる） |
| 複数行 | 文字列の中の改行は、そのまま文字列に入る（今までどおり） |

#### 分割代入（v0.26.0）

```
{@a, @b} := {1, 2}
{@head, ...@tail} := @list
{"x": @x, "y": @y} := @point
{"pos": {@px, @py}} = @entity     // 入れ子もよい。`=` なら宣言済みの変数に代入
```

左辺は、配列のパターン `{@a, @b, ...@rest}` かマップのパターン `{"キー": パターン}`。右辺の型が合わない、要素が足りない、キーがないときは実行時エラー（`...@rest` のないパターンは、余った要素があってもエラーにしない）。

#### ビット演算（v0.27.0）

整数型は作らない（数値は 64 ビット浮動小数点数のまま、2^53 までの整数は正確）。ビット演算は `import["std:bits"]` の関数にする。

| 関数 | 内容 |
|---|---|
| `and[a, b]` `or[a, b]` `xor[a, b]` `not[a]` | ビットごとの演算。引数は整数（±2^53 以内）で、64 ビットの 2 の補数として計算する |
| `shl[a, n]` `shr[a, n]` | 左・右（算術）シフト。`n` は 0〜63。結果が ±2^53 を超えるときは実行時エラー |
| `popcount[a]` | 立っているビットの数（`a` は 0 以上） |

### 5.20 正規表現（`std:regex`、v0.28.0、確定 2026-10-12）

F2 の方針（2026-10-12）: 順序は **regex → TCP → WebSocket → 非同期 → sqlite**。regex は外部の `regex` クレート（`regex` feature、既定で有効）を使う。sqlite は後回し。

```
@re := import["std:regex"]
@m := @re.find["(\\d+)-(\\d+)", "tel 03-1234"]
log[@m.text, @m.groups, @m.start]          // "03-1234" {"03", "1234"} 4
@re.replace_all["\\s+", "a  b   c", " "]   // "a b c"
```

パターンは `regex` クレートの構文（Perl 風。後方参照と先読みは使えない。`\d` `\w` `\s`、`(?i)` などのフラグ、名前つきグループ `(?P<name>…)`）。文字列の `\` は 2 つ書くか、生の文字列（5.19）を使う（`r"(\d+)-(\d+)"`）。

| 関数 | 内容 |
|---|---|
| `is_match[pattern, s]` | 一致する部分があるか（真偽値） |
| `find[pattern, s]` | 最初の一致の**一致マップ**。なければ `nil` |
| `find_all[pattern, s]` | すべての一致（重ならない）の一致マップの配列 |
| `replace[pattern, s, replacement]` | 最初の一致だけ置き換えた文字列 |
| `replace_all[pattern, s, replacement]` | すべての一致を置き換えた文字列 |
| `split[pattern, s]` | 一致で区切った文字列の配列 |
| `escape[s]` | 正規表現として特別な文字をエスケープした文字列 |

**一致マップ**: `{"text": 一致した文字列, "start": 開始位置, "end": 終了位置, "groups": グループ 1 以降の文字列の配列（参加しなかったグループは nil）, "named": 名前つきグループのマップ（参加しなければ nil）}`。位置は文字単位（`str_sub` などと同じ。バイトではない）。

`replacement` は、文字列か関数。文字列では `$1` `${1}` `${name}` で一致したグループを入れる（`$$` は `$`。ないグループは空）。関数なら、一致マップを受け取って置き換える文字列を返す（返り値が文字列でなければ実行時エラー）。

| 項目 | 内容 | 状態 |
|---|---|---|
| パターンの間違い | エラー値（種類 `parse`）。プログラムに書いたパターンの間違いも、実行時に作ったパターンも同じ扱い | 確定 |
| 大きすぎるパターン | `regex` クレートの上限を超えたらエラー値（種類 `parse`） | 確定 |
| 速度 | 同じパターンは内部で使い回す（最近の 64 個まで）。入力の長さに比例する時間で一致する（指数的に遅くならない） | 確定 |
| 空の一致 | `find_all` `replace_all` `split` は、空の一致（`x*` など）も `regex` クレートと同じ規則で扱う | 確定 |
| ビルド | `regex` feature（既定で有効）。外した版で `import["std:regex"]` すると、含まれていないことを案内する | 確定 |

### 5.21 TCP（`std:net`、v0.29.0、確定 2026-10-12）

ブロッキングの TCP ソケット（8.3: 順番に進む処理はブロッキング関数で書く。待っている間は、そのインタプリタのスレッドが待つだけ）。TLS は扱わない。

```
@net := import["std:net"]
@conn := @net.connect["example.com", 80]?
@net.write[@conn, "GET / HTTP/1.0\r\n\r\n"]?
log[@net.read_line[@conn]?]
@net.close[@conn]
```

#### ハンドルの型

接続（`connect` と `accept` の結果）と待ち受け（`listen` の結果）は、新しい値の型 **`handle`**（`type_of` は `"handle"`）。表示は `<tcp 接続 127.0.0.1:80>` / `<tcp 待ち受け 127.0.0.1:8080>`（閉じていれば `<tcp 閉じています>`）。`==` は同じハンドルかを比べる。JSON にはできない（実行時エラー）。参照されなくなったハンドルは自動で閉じる。

#### 関数

| 関数 | 内容 |
|---|---|
| `connect[host, port]` `connect[host, port, options]` | 接続したハンドル。`options` は `{"timeout": 秒}`（接続のときだけの時間切れ。省略は 30） |
| `listen[port]` `listen[options]` | 待ち受けのハンドル。`options` は `{"port": 0〜65535, "host": "127.0.0.1"}`（`port` が 0 なら空いているポート）。`host` の既定は `"127.0.0.1"` |
| `accept[listener]` | 接続を 1 つ受け付けて、接続のハンドルを返す（来るまで待つ） |
| `read[conn, n]` | 最大 `n` バイトを読んでバイト列で返す（届いている分だけ。相手が閉じていれば空のバイト列） |
| `read_exact[conn, n]` | ちょうど `n` バイト読む。足りないうちに閉じたら、エラー値（種類 `eof`） |
| `read_line[conn]` | 改行までの 1 行を文字列で返す（末尾の `\n` と `\r\n` は除く）。相手が閉じて何も読めなければ `nil`。UTF-8 でなければ `parse` のエラー値 |
| `write[conn, data]` | 文字列かバイト列を全部送る。戻り値は `nil` |
| `close[handle]` | 閉じる。何度呼んでもよい |
| `set_timeout[conn, seconds]` | 以降の `read` `write` の時間切れ。`nil` で時間切れなし（既定） |
| `local_addr[handle]` `peer_addr[conn]` | `{"host": "127.0.0.1", "port": 8080}` |

| 項目 | 内容 | 状態 |
|---|---|---|
| 失敗 | エラー値。種類は `timeout`（時間切れ）、`eof`（`read_exact` で足りない）、`closed`（閉じたハンドルの使用）、`parse`（`read_line` が UTF-8 でない）、`network`（そのほか。名前が引けない、接続できない、切断されたなど） | 確定 |
| 型の間違い | 接続でないハンドルを `read` に渡す、`n` が負など、プログラムの間違いは実行時エラー | 確定 |
| 行の読み込み | 1 行は 16 MB まで。超えたら `network` のエラー値 | 案 |
| バッファ | `read` `read_line` `read_exact` は、ハンドルの内部で読み込みをまとめる。同じ接続では、どれを混ぜて呼んでもバイトの順序は保たれる | 確定 |
| 同時に待つ | 1 つのインタプリタが 1 つずつ待つ。同時の接続を捌く道具は、非同期の関数（F2 の後半）で作る | 確定 |
| ビルド | 標準ライブラリだけ（外部クレートなし）。feature はなし | 確定 |

### 5.22 WebSocket（`std:ws` と `http.serve`、v0.30.0、確定 2026-10-12）

RFC 6455。サーバー側は `http.serve` のハンドラが「この接続を WebSocket にする」と返し、**コールバック**（イベント駆動）で扱う。クライアント側は `std:ws` のブロッキング関数（5.21 の TCP と同じ書き方）。TLS（`wss://`）は後回し。

#### サーバー

```
@http := import["std:http"]
@ws := import["std:ws"]
@http.serve[8080, [@req] (
    if @req{"path"} == "/chat" (
        # {"websocket": {
            "on_open": [@conn] ( @ws.send[@conn, "ようこそ"] ),
            "on_message": [@conn, @msg] ( @ws.send[@conn, "echo: @msg"] ),
            "on_close": [@conn, @code] ( log["切断", @code] )
        }}
    )
    # {"status": 404, "body": "not found"}
)]
```

| 項目 | 内容 | 状態 |
|---|---|---|
| 返し方 | ハンドラの戻り値のマップの `websocket` キー（`status` `headers` `body` `json` とは同時に使えない）。値は `on_open` `on_message` `on_close` を持つマップ（どれも省略できる。ほかのキーは実行時エラー） | 確定 |
| 条件 | リクエストが WebSocket の接続要求（`Upgrade: websocket`、`Sec-WebSocket-Key`、バージョン 13）でなければ `400` を返し、メッセージを標準エラーに出す | 確定 |
| `on_open[conn]` | 接続が確立した直後 | 確定 |
| `on_message[conn, message]` | メッセージを受け取るたび。テキストは文字列、バイナリはバイト列。断片化されたメッセージは、まとめてから渡す | 確定 |
| `on_close[conn, code]` | 接続が終わったとき（相手が閉じた、`close` を呼んだ、通信が切れた）。`code` は相手が送った終了コード（なければ 1005、異常な切断は 1006）。1 つの接続につき 1 回 | 確定 |
| 実行 | コールバックは、HTTP のハンドラと同じインタプリタのスレッドで、**1 つずつ順番に**呼ぶ（5.16）。待ち受け・フレームの解析・送信は補助スレッド。コールバックのエラーは標準エラーに出して続ける（その接続も続く） | 確定 |
| `conn` | ハンドル（5.21）。サーバー側の接続は `send` `close` だけ使える（`recv` は実行時エラー。受け取りはコールバック） | 確定 |

#### `std:ws`

| 関数 | 内容 |
|---|---|
| `connect[url]` `connect[url, options]` | `ws://host[:port]/path?query` に接続して、接続のハンドルを返す。`options` は `{"headers": {…}, "timeout": 秒}`（`timeout` は接続とハンドシェイクのとき。省略は 30） |
| `send[conn, data]` | 文字列はテキスト、バイト列はバイナリで送る。戻り値は `nil` |
| `recv[conn]` | クライアントの接続だけ。次のメッセージを待って返す（文字列かバイト列）。接続が閉じたら `nil`。ping には自動で pong を返す |
| `close[conn]` `close[conn, code, reason]` | 閉じる（close フレームを送る）。既定の `code` は 1000。何度呼んでもよい |
| `set_timeout[conn, seconds]` | クライアントの `recv` の時間切れ。`nil` で時間切れなし（既定） |

| 項目 | 内容 | 状態 |
|---|---|---|
| 失敗 | エラー値。種類は `timeout` `closed`（閉じた接続の使用）`network`（接続・通信の失敗、ハンドシェイクの失敗、`wss://` 未対応）`protocol`（相手が RFC に反するフレームを送った）`too_large`（メッセージが 16 MB を超えた）`parse`（テキストが UTF-8 でない） | 確定 |
| フレームの規則 | クライアントのフレームはマスクする。サーバーはマスクされていないフレームを `1002` で拒否する。制御フレーム（ping・pong・close）は 125 バイトまで。メッセージは 16 MB まで（超えたら `1009` で閉じる）。テキストが UTF-8 でなければ `1007` で閉じる | 確定 |
| 送信 | `send` は待たずに戻る（サーバーの接続は送信用のキューに積む。クライアントは書き込みまで待つ） | 確定 |
| `Origin` `Sec-WebSocket-Protocol` | 見ない・扱わない（認証や許可は、ハンドラが `@req{"headers"}` を見て決める） | 確定 |
| 圧縮（permessage-deflate） | 扱わない（申し出られても使わない） | 確定 |
| 同時接続 | `http.serve` の 256 接続の上限に含む | 確定 |
| `wss://` | 後回し（TLS を直接扱う実装が要る） | 後回し |
| ビルド | `http_server`（`http` feature）の中。`std:ws` は標準ライブラリだけで、feature なし（SHA-1 は自前で書く） | 確定 |

### 5.23 非同期の関数（`std:async`、v0.31.0、確定 2026-10-12）

8.3 の方針どおり、**インタプリタは 1 スレッドのまま**で、順番に進む処理はブロッキング関数で書く。同時に進めたいものだけ、**コールバック型**の関数を使う。`await` は作らない（VM を作るときに、この仕組みを下地にして構文だけ足す）。

```
@async := import["std:async"]
@http := import["std:http"]

@async.after[1.5, [] ( log["1.5 秒後"] )]
@http.get_async["https://example.com/a", [@r] ( log["a:", @r{"status"}] )]
@http.get_async["https://example.com/b", [@r] ( log["b:", @r{"status"}] )]   // a と同時に進む
log["先にここまで進む"]
// スクリプトの最後で、待っているものがなくなるまで待つ
```

#### イベントループ

| 項目 | 内容 | 状態 |
|---|---|---|
| 仕組み | 補助スレッドで進めた処理の結果は、`Send` できるデータ（数値・文字列・バイト列・配列・マップ・エラー値）にして、インタプリタのスレッドのキューに届く。インタプリタは、届いた順に**コールバックを 1 つずつ**呼ぶ。コールバックの中は、普通のコードと同じ（途中で割り込まれない） | 確定 |
| いつ動くか | スクリプトの最後（本体を実行し終えた後）に、待っているものがある間（タイマーと、結果待ちの非同期の関数）だけ、自動で動く。なくなれば終了する。`http.serve` は、このイベントループの上で動く（サーバーがある間は終わらない）。対話モード（REPL）では動かさない | 確定 |
| `async.run[]` | その場でイベントループを動かし、待っているものがなくなるまで（`stop[]` まで）戻らない。イベントループの中（コールバックの中）から呼ぶと実行時エラー | 確定 |
| `async.stop[]` | 実行中のコールバックが終わったら、イベントループを止める（待っているものは捨てる）。`run[]` / `http.serve` が戻る | 確定 |
| エラー | コールバックの中の実行時エラーは、位置と呼び出し履歴を標準エラーに出して、イベントループは続ける。`os.exit` は全体を止める | 確定 |
| 順序 | 結果が届いた順（タイマーは、時刻が来た順）。同時に届いたものの順は決まらない | 確定 |

#### 関数

| 関数 | 内容 |
|---|---|
| `after[seconds, f]` | `seconds` 秒（0 以上の数）後に、引数なしで `f` を 1 回呼ぶ。戻り値は番号（`cancel` に渡す） |
| `every[seconds, f]` | `seconds` 秒（0 より大きい数）ごとに、引数なしで `f` を呼び続ける（`cancel` するまで）。戻り値は番号 |
| `cancel[id]` | タイマーを止める、または非同期の関数の結果を捨てる（コールバックを呼ばない）。知らない番号・終わったものは何もしない |
| `run[]` `stop[]` | 上のとおり |

非同期の関数は、ブロッキング版の名前に `_async` をつけ、**最後の引数にコールバック**を足した形（ほかの引数と、省略できる引数の規則は同じ）。コールバックは、ブロッキング版が返す値（成功の値か、エラー値）を **1 つ**受け取る。戻り値は番号（`cancel` に渡せる）。

| 非同期の関数 | ブロッキング版 |
|---|---|
| `http.request_async[options, f]` `http.get_async[url, f]` `http.get_async[url, options, f]` `post_async` `put_async` `delete_async` | `http.request` `get` `post` `put` `delete`（5.11） |
| `os.run_async[command, args, f]` `os.run_async[command, args, options, f]` | `os.run`（5.13） |

| 項目 | 内容 | 状態 |
|---|---|---|
| 引数の検査 | 引数の間違い（型・オプション）は、呼んだ時点で実行時エラー（ブロッキング版と同じ）。通信の失敗などは、コールバックにエラー値で届く | 確定 |
| 待っている数の上限 | 10000 まで。超えたら実行時エラー | 確定 |
| `os.run_async` の出力 | 子プロセスの出力は、結果のマップ（`stdout` `stderr`）に入るだけで、`log` とは混ざらない | 確定 |
| ほかのブロッキング関数 | ファイル・TCP・WebSocket の非同期版は作らない（必要になったら足す）。コールバックの中でブロッキング関数を呼ぶと、その間はほかのコールバックも待つ | 確定 |
| 数 | タイマーと非同期の関数 1 つにつき補助スレッドを 1 つ使う | 確定 |

### 5.24 `ui`（`std:ui`、v0.32.0、確定 2026-10-12）

G（表示とアプリ）の最初。8.3 の **Elm 型**（GUI はメインスレッド、インタプリタは専用スレッド、メッセージでつなぐ）と、8.4 の**宣言的 UI**（状態が変わるたびに、画面を返す関数を呼び直す）で作る。裏側の描画は egui（eframe）。`canvas`（図形・画像・キー入力・ゲームのループ）と音は、次の版以降に分ける。

```
@ui := import["std:ui"]
@count := 0
@name := ""
@ui.run[[] (
    # @ui.column[{
        @ui.text["回数: @count", {"size": 24}],
        @ui.row[{
            @ui.button["増やす", [] ( @count = @count + 1 )],
            @ui.button["リセット", [] ( @count = 0 )]
        }],
        @ui.text_input[@name, [@v] ( @name = @v ), {"hint": "名前"}],
        @ui.text["こんにちは、@{@name}さん"]
    }]
), {"title": "カウンター", "width": 360, "height": 240}]
```

#### 仕組み

| 項目 | 内容 | 状態 |
|---|---|---|
| スレッド | メインスレッドが GUI（egui）を担当し、インタプリタは今までどおり専用スレッドで動く。画面は、`Send` できる木（`ui` の部品のデータ）にして GUI に送り、操作（クリックや入力）は、イベントループ（5.23）にメッセージで届く。関数値は GUI に持ち出さず、番号で呼ぶ（8.3） | 確定 |
| `ui.run[view]` `ui.run[view, options]` | ウィンドウを開き、`view`（引数なしで、画面を返す関数）を呼んで表示する。操作のコールバックが呼ばれるたびに、`view` を呼び直して画面を更新する。ウィンドウが閉じられるまで戻らず、戻り値は `nil`。この間も、タイマーや非同期の関数（5.23）は動く | 確定 |
| `options` | `{"title": "…", "width": 640, "height": 480, "font": "フォントのパス"}`（どれも省略できる。既定は `"Dolphin"` と 640×480） | 確定 |
| `ui.refresh[]` | いますぐ `view` を呼んで、画面を更新する。タイマーや非同期のコールバックで状態を変えたとき（操作のコールバック以外）に呼ぶ | 確定 |
| `ui.quit[]` | ウィンドウを閉じる | 確定 |
| 1 プロセスに 1 つ | `ui.run` は 1 回だけ（ウィンドウのループを作り直せないプラットフォームがあるため）。2 回目は実行時エラー | 確定 |
| コールバックの中のエラー | 標準エラーに出して続ける（5.23）。`view` の中のエラーも同じで、画面は前のまま | 確定 |

#### 部品

部品は `std:ui` の関数が返す値で、`view` の戻り値としてつなぐ。`nil` は、その場所に何も置かない（`if` の式で出し分けられる）。`view` が配列を返したときは、縦に並べる。

| 関数 | 内容 |
|---|---|
| `text[s]` `text[s, options]` | 文字。`options` は `{"size": 文字の大きさ, "color": "#rrggbb", "bold": 真偽値}` |
| `button[label, on_click]` `button[label, on_click, options]` | ボタン。押されると `on_click[]`。`options` は `{"enabled": 真偽値}` |
| `text_input[value, on_change]` `text_input[value, on_change, options]` | 文字の入力欄。変更のたびに `on_change[新しい文字列]`。`options` は `{"hint": 薄く出す文字, "multiline": 真偽値, "password": 真偽値}`。入力欄に表示するのは `value`（コールバックで状態に入れないと、入力は元に戻る） |
| `checkbox[label, checked, on_change]` | チェックボックス。変更で `on_change[新しい真偽値]` |
| `slider[value, min, max, on_change]` | スライダー。動かすと `on_change[新しい値]` |
| `select[labels, index, on_change]` | 選択（ドロップダウン）。`labels` は文字列の配列、`index` は選ばれている番号。選ぶと `on_change[番号]` |
| `progress[fraction]` | 進捗バー。`fraction` は 0〜1 |
| `column[children]` `row[children]`（+ `options`） | 縦・横に並べる。`options` は `{"spacing": 間隔}` |
| `group[children]` | 枠で囲んで縦に並べる |
| `scroll[child]` | 縦にスクロールできる領域 |
| `separator[]` `space[n]` | 区切り線、`n` ピクセルの空き |

引数の間違い（型、知らないオプション、`on_change` が関数でないなど）は、部品を作った時点の実行時エラー。部品の `children` の要素が部品でなければ、`view` を呼んだ時点の実行時エラー。

#### 日本語

egui の標準フォントに日本語がないので、起動時に**システムのフォントを探して読み込む**（Windows は游ゴシック・メイリオ、macOS はヒラギノ、Linux は Noto Sans CJK・IPA など）。見つからなければ、`options` の `font`（`.ttf` `.otf` `.ttc`）を使う。どちらもなければ日本語は表示できない（豆腐になる）ので、標準エラーに警告を出す。

#### ビルド

| 項目 | 内容 | 状態 |
|---|---|---|
| `ui` feature | **既定では無効**（`cargo build --features ui`）。eframe は依存が多く、ビルドに時間がかかり、実行ファイルも大きくなるため。外した版で `import["std:ui"]` すると、含まれていないことを案内する | 確定 |
| メインスレッド | `ui` を有効にした版は、メインスレッドでウィンドウのループを待ち受ける（`ui.run` が呼ばれるまでは、今までどおり動く） | 確定 |
| 検証 | 画面の描画は自動テストできないので、部品の木への変換と、コールバックの番号の管理を単体テストにし、描画は手で確かめる | 確定 |

## 6. 旧実装からの主な変更（案）

| 旧実装 | 作り直し版 | 理由 |
|---|---|---|
| 1行ずつ文字列を分割して評価 | トークン化 → 構文解析 → AST → 評価 | 目的（処理系の仕組みの理解）に合わせる |
| 式の括弧が使えない | `( )` でグループ化できる | 4.1 の規則で区別できる |
| 行末コメントで行が無視される | 行末コメントを許す | |
| `$n * -1` が動かない | 単項 `-` を追加 | |
| エラーに行番号がない | 行・列を表示 | |
| 引用符なしの文字列（`@name = dolphin`） | `"..."` で囲む（確定） | Lexer で識別子と区別するため |
| 組み込み関数は出力引数で結果を返す（`arr_len[nums, @len]`） | 戻り値で返す（`@len = arr_len[@nums]`）（確定） | ユーザー定義関数と同じ形にし、式の中で使えるようにする |
| 真偽値は 1 / 0 | `true` / `false`（確定） | JSON との対応 |
| `@`（グローバル）と `$`（ローカル）の 2 種類 | `@` だけ。スコープは宣言の場所で決まる（確定 2026-10-11） | クロージャを入れるため。`@` の個性は残す |
| 最初の代入で宣言 | `:=` で宣言、`=` は代入のみ（確定 2026-10-11） | 外側の変数の書き換えと新規宣言を区別する。タイプミスも検出できる |
| 配列の添字は `@a[0]` | `@a{0}`（確定 2026-10-11） | 関数値の呼び出し `@f[0]` と見分けるため |

## 7. 未決事項

決定済み（2026-10-04）: 文字列は引用符で囲む、組み込み関数は戻り値で返す、真偽値は `true` / `false`。内容は 3〜6 章に反映した。

### 7.1 配列の渡し方（決定済み 2026-10-06）

**参照渡し**に決定。配列とマップは、関数に渡しても変数に代入しても同じものを指す（Python、JavaScript と同じ）。

```
@a = {1, 2}
@b = @a
arr_push[@b, 3]
log[@a]        // {1, 2, 3}
```

理由: 実装が軽く（`Rc<RefCell<…>>` を共有するだけ）、`arr_push` のようにその場で書き換える関数を自然に書ける。

### 7.2 `gameloop`

旧実装では `gameloop ( ... )` がキーワード付きブロックだった。**キーワードにはしない**（2026-10-11）。関数値とイベントループ（8 章）を入れたうえで、`ui` / `canvas` ライブラリが「毎フレーム呼ぶ関数」を受け取る形にする。

## 8. 方向の見直し（2026-10-11）

最終目標は、実用レベルの言語にすること（Yay! API クライアント、デスクトップアプリ、ゲームが書ける）。今の設計に無理に合わせず、土台から見直す。GUI の機能を足す前に、言語の土台を先に変える。

### 8.1 ロードマップ（2026-10-12 に見直し）

特定のアプリのための実装に偏らず、Python や Node のような言語に普通あるものを、依存の少ない順に厚くする。

| 順 | 内容 | 状態 |
|---|---|---|
| 完了 | 文法の見直し（`$` 廃止、`:=`、添字 `{ }`）、関数値とクロージャ、`nil`・`for`・`range`、エラー値と `?`、組み込みモジュールと JSON、HTTP クライアント（v0.5.0〜v0.10.0） | 確定 |
| A | **基本型の関数の穴**: `type_of`、配列（`sort` `slice` `reduce` など）、マップ（`values` `items` `merge` など）、文字列（`starts_with` `pad_left` など）、数値の書式、`std:math`（5.12） | 完了（v0.11.0） |
| B | **システムまわり**: `std:time`、`std:os`（引数・環境変数・終了コード・外部コマンド）、`std:path`、ファイルの残り（一覧・作成・削除・名前変更・情報） | 完了（v0.12.0） |
| C | **バイナリとハッシュ**: バイト列の型（5.14）、バイナリのファイル入出力、`std:encoding`（base64・hex・URL）、`std:crypto`（sha1・sha256・sha512・md5・hmac・uuid・乱数） | 完了（v0.13.0） |
| F1 | **メモリ回収器**（5.15）、**HTTP サーバー**（5.16）。実行モデル（8.3）のうち、インタプリタ専用スレッドと補助スレッドとのメッセージのやり取りをサーバーで実装する | 完了（v0.15.0 回収器、v0.16.0 サーバー） |
| D | **開発の道具**: `assert`、`dbg`、`dolphin check`、`dolphin test`（5.17、v0.17.0）、`dolphin fmt`（5.18、v0.18.0） | 完了（v0.18.0） |
| E | **言語の書き心地**（5.19）: 数値リテラル、組み込み関数を隠す定義、`@m.key`、条件式、引数の既定値、可変長引数、文字列の式展開と生の文字列、分割代入、ビット演算（v0.19.0〜v0.27.0） | 完了（v0.27.0） |

| G | **表示とアプリ**: `ui`（5.24、v0.32.0、完了）→ `canvas`・画像 → 音 | 実装中 |

最終目標は「一般的な言語と遜色なく、9 割のことができる」こと。バックエンド（F1）とデスクトップ（G）を、できるだけ早く書ける状態にする。

順序の理由: A〜C は依存が少なく確実で、バイト列の型はサーバーの本文・画像・暗号のすべての土台になる。F1 でバックエンドを書けるようにしてから、D（テスト）と E（書き心地）で言語を磨く。E は、実際にコードをたくさん書いた後のほうが、何が不便か分かって決めやすい。

### 8.2 関数値とクロージャ

5.8 に移した。無名関数は `[` で始まるので、今の文法と衝突しない（式の先頭に `[` が来る場面がない）。

### 8.3 実行モデル（決定済み 2026-10-11）

**Elm 型**: GUI とインタプリタを別のスレッドに置き、メッセージでつなぐ。

```
 メインスレッド          インタプリタのスレッド（大きなスタック）        補助スレッド
 ┌────────────┐  イベント  ┌─────────────────────────────┐  結果   ┌────────────┐
 │ GUI（描画・入力）│ ───────▶ │ イベントループ: 受け取って関数を呼ぶ │ ◀────── │ 通信・タイマー │
 │            │ ◀─────── │ 画面（データ）を作って送る        │ ──────▶ │            │
 └────────────┘  画面     └─────────────────────────────┘  依頼   └────────────┘
```

| 項目 | 内容 | 状態 |
|---|---|---|
| インタプリタ | 1 スレッドのまま。`Rc` を使い続ける。スタックの大きい専用スレッドで動かす | 確定 |
| スレッドをまたぐ値 | データ（数値・文字列・真偽値・配列・マップ）だけ。関数値は持ち出さず、番号で呼ぶ | 確定 |
| メインスレッド | GUI だけを担当する。macOS はメインスレッドでウィンドウのループを動かす必要があるため | 確定 |
| 通信・ファイル | 順番に進む処理は**ブロッキング関数**（`http_get[url]` が結果を返す）で書く。インタプリタのスレッドが待つだけで、画面は固まらない | 確定 |
| ブロッキング中のイベント | 溜めておき、終わってから順に処理する。ロード中の表示は、通信の前に `ui.refresh[]` で先に出す | 案 |
| 同時進行 | コールバック型の関数（`http_get_async[url, @cb]`）を別に用意する。コールバックは結果の値を 1 つ受け取る | 案 |
| `await` | 作らない。VM（段階 6）を作ったときに、コールバック型を下地にして構文だけ足す | 後回し |
| 実行中のエラー | 画面を持つアプリは、落とさずエラーを画面かターミナルに出す | 案 |

後回しの理由: 順番に進む処理はブロッキングで足りる。`await` が必要になるのは、並列取得やループの中の非同期、大量リクエストを捌くサーバーで、すぐには要らない。

### 8.4 `ui` ライブラリ

```
@count := 0
ui.run[[] (
    # ui.column[{
        ui.text["回数: @count"],
        ui.button["増やす", [] ( @count = @count + 1 )]
    }]
)]
```

- 画面を返す関数を書き、状態が変わるたびに呼び直す（宣言的 UI）
- 裏側の描画は、最初は egui（即時モード）で実装する。ユーザーから見えるのは `ui.*` の API だけで、後から差し替えられる
- 日本語表示のため、システムフォントの読み込みか同梱フォントが必要（macroquad も egui も標準フォントに CJK がない）

### 8.5 標準ライブラリの名前（決定済み 2026-10-11）

| 項目 | 内容 | 状態 |
|---|---|---|
| 基本の関数 | 接頭辞で分ける（`str_` `arr_` `map_` `file_` など）。メソッド形（`@s.upper[]`）は採らない。後から足すことはできる | 確定 |
| 名前の付け方 | `型名_動詞`、対象の値を最初の引数にする（`arr_push[a, v]`、`str_split[s, sep]`） | 確定 |
| 大きいライブラリ | `json` `http` `ui` `canvas` `time` などは組み込みモジュールにして、`@ui := import["std:ui"]` で名前空間に入れる。呼び方は通常のモジュールと同じ（`@ui.run[...]`） | 確定 |
| 組み込みモジュールの実装 | `Module` に組み込み関数の表を持たせ、`import["std:..."]` で返す | 案 |
| 名前の衝突 | 組み込み関数と同じ名前の関数は定義できない（今のまま）。1.0 までは、標準ライブラリを足して衝突したら、ユーザー側で直す | 案 |

### 8.6 エラー処理（決定済み 2026-10-11）

エラーを 2 種類に分ける。

| 種類 | 例 | 扱い |
|---|---|---|
| 外の世界の失敗 | ファイルがない、通信できない、JSON が壊れている、`to_num["abc"]` | **エラー値を返す**。呼ぶ側が見て対処する |
| プログラムの間違い | 型が違う、添字が範囲外、未定義の変数、引数の数 | 今までどおり**実行時エラーで止まる** |

```
@text := file_read["a.txt"]
if is_error[@text] (
    log["失敗: ", err_message[@text]]
)

// 失敗したら、その関数からエラーをそのまま返す
load[@path] (
    @text := file_read[@path]?
    @n := to_num[str_trim[@text]]?
    # @n * 2
)
```

| 項目 | 内容 | 状態 |
|---|---|---|
| エラー値 | 新しい型（`エラー`）。種類（`kind`、`"not_found"` のような文字列）とメッセージを持つ | 確定 |
| 失敗しうる関数 | 成功なら通常の値、失敗ならエラー値を返す。`file_read` `file_write` `file_append` `to_num` のほか、これから足す `json_parse` `http_*` など | 確定 |
| 関数 | `is_error[v]`（真偽値）、`err_kind[e]`、`err_message[e]`、`err_new[kind, message]`（自分で作る） | 確定 |
| `?`（後置） | `式?`。値がエラーなら、いまの関数（無名関数を含む）からそのエラーを返す。エラーでなければ、その値になる。関数の外で使ってエラーになったら、実行時エラーで止まる | 確定 |
| 放置の禁止 | 式文の値がエラーなら、実行時エラーにする（`file_write[...]` の失敗に気づかないまま進まないため）。変数に入れるか、`?` を付けるか、`is_error` で見ればよい | 確定 |
| エラー値の誤用 | `if` の条件や演算にエラー値を使ったら、実行時エラー（型が違う場合と同じ） | 確定 |
| 比較 | `==` は種類とメッセージが同じなら true | 案 |
| 表示 | `<エラー not_found: メッセージ>` | 案 |
| コールバック | 非同期関数（`http_get_async[url, @cb]`）は、成功の値かエラー値を 1 つ渡す | 案 |
| 種類の例 | `not_found` `permission` `io` `parse`（文字列や JSON の形式）`network` `timeout` | 案 |
